## Identity, Config & Determinism Spine

**Location:** `experiments/kernel_demo.py` (lines 1–251, 917–989, 1534–1546, 2829–2847)

**Responsibility:** Establishes the run's identity — a source-text hash of the code's own "semantic surface", a hash of the pre-registered config block, labelled seed derivation, scoped RNG, Class-1 determinism knobs, a zero-normalized parameter-state hash and an environment fingerprint — so that every downstream record can be bound to the exact code, config and machine that produced it, and any later divergence can be refused rather than silently absorbed.

**Key Components:**
- `semantic()` (line 60) — identity decorator; appends the class/function to the module-global `_SEMANTIC_SURFACE` list (:57) at **import** time and returns it unchanged (no runtime behaviour). The comment at :61–63 records the rev-3 defect it fixes: call-time registration made the set of registered objects depend on how far a process had progressed, so a worker mid-episode and a fresh parent computed different hashes.
- `semantic_const(name, value)` (line 71) — registers behaviour-changing module constants (which have no source text to hash) into `_SEMANTIC_CONSTANTS` (:68); raises `ValueError` on a duplicate name (:81–82). The docstring states the inclusion rule precisely: register iff changing the value changes computed numbers or gate outcomes; documentation-only lists and independently-recorded identities stay out (:76–80). Eleven registrations exist, confirmed by importing the module (`CIFAR_MEAN_RGB` :244, `CIFAR_STD_RGB` :245, `TELEMETRY_DIM` :351, `EPOCH_FEATURE_IDX` :352, `PATHOLOGIES` :539, `DESIGNED_WINNER` :543, `SEED_NAMES` :634, `REPLAY_REFUSAL_KEYS` :952, `AGREEMENT_MARGIN` :3256, `N_EVAL_REFANS` :3257, `EVAL_COMPARATORS` :3261).
- `_NON_SEMANTIC` (line 87) — the explicit opt-out register: symbol name → stated reason. Six seeded at :91–96, five appended at the point of definition (:504, :1204, :1424, :3127, :3128) — 11 opt-outs against 109 registered surface objects (both counts confirmed by importing the module). Enforced out-of-band by `tests/unit/kernel_demo/test_derive.py:93`, which fails on any public class/function defined in the module that is neither on `_SEMANTIC_SURFACE` nor in `_NON_SEMANTIC`.
- `config_hash()` (line 231) — SHA-256 over `inspect.getsource(obj)` for every registered object, **sorted by source text** (:233), then `name=repr(value)` for every semantic constant in sorted name order (:235–236). Sorting makes the digest independent of registration order. This is the code's answer to "which version of itself produced this result": consumed as a refusal key by `--collect` (:3151), `--train` (:3343), `--eval` (:3463) and `--replay` (:3946), and pinned into the freeze manifest (:2874).
- `frozen_block_hash(cfg)` (line 226) — SHA-256 over sorted `k=repr(getattr(cfg,k))` lines for the 34 names in `FROZEN_FIELDS` (:188–223). Separate from `config_hash` because `Config` is deliberately `_NON_SEMANTIC` (:91); :3948–3950 states the consequence explicitly — without this second check a frozen-constant edit would move *neither* hash and would then masquerade downstream as a kernel-selection (GPU nondeterminism) divergence.
- `Config` (line 137) — frozen dataclass, 39 fields in five commented groups: frozen lifecycle+reward (:139–154), frozen statistics (:156–160), frozen gate thresholds (:162–168), frozen policy-training schedule (:170–173), and "NOT frozen" (:175–179). :180–185 adds `batch_size` and `run_seed` to the frozen block *beyond* the spec's list, with the stated argument that both are trajectory-defining and no other hash covers them. The frozen/unfrozen split is the pre-registration boundary: frozen fields cannot move without a refusal firing; the five unfrozen fields (`n_collect`, `d_model`, `n_layers`, `eval_chunk`, `fsync_every`) are described at :91 as "licensed operational levers".
- `derive(seed, *labels)` (line 101) — SHA-256 of `seed.to_bytes(8,"big")` followed, per label, by a 4-byte big-endian **length prefix** then the UTF-8 bytes (:105–107); returns the first 8 digest bytes as a uint64 (:108). The length prefix makes the encoding unambiguous, so `derive(1,"a:b","c") != derive(1,"a","b:c")` (asserted at `test_derive.py:20`). Order-sensitive, deterministic, and closed under itself (output is always < 2^64, so `derive(derive(s,"a"),"b")` is safe). Roughly 40 distinct label namespaces are in use across the file (`"valsplit"` :263, `"pathology"` :1017, `"host-init"` :1018, `"future"` :1020, `"arm"` :1174, `"tune-split"` :1543, `"probe-split"` :2592, `"derangement"` :3286, `"money"` :3716, …).
- `make_generator(seed, device)` (line 112) — `torch.Generator(device).manual_seed(seed)`; the comment at :114–116 records two deliberate decisions: the full uint64 is passed unmasked (masking would alias seeds), and CPU/CUDA generators are not comparable, so all current call sites use the CPU default.
- `rng_scope(gen)` (line 123) — contextmanager that saves the process-global CPU RNG state (:127), installs the named generator's state (:128), and in a `finally` writes the advanced global state back into `gen` and restores the prior global (:131–133). Existence rationale at :124–126: `nn.Module` constructors draw from the global stream inside `reset_parameters()` and accept no `generator=` argument, so this is the only way to make module construction reproducible.
- `enable_class1()` (line 917) — the determinism knob block: refuses a stray `CUBLAS_WORKSPACE_CONFIG` rather than tolerating it (:919–924, "a tolerated stray value is a silent Class-1 relaxation"), then `use_deterministic_algorithms(True)`, `cudnn.deterministic=True`, `cudnn.benchmark=False`, and TF32 off on both the matmul and cuDNN paths (:925–929).
- `state_hash(module)` (line 933) — hashes `state_dict()` in sorted key order; per tensor: `detach().cpu().contiguous()`, then `torch.where(v==0, zeros_like(v), v)` to collapse `-0.0` onto `+0.0` (the D8 zero-normalization, :934–935), then `name` + 8-byte length prefix + raw bytes. Aliased to `host_init_hash` (:950) so the retired standalone version stays on the surface by object identity rather than by a second registration. Also used to key policy checkpoints (`ckpt_id = state_hash(policy)`, :3364).
- `env_block(device, worker_count)` (line 969) — records torch/CUDA/cuDNN/Python versions, GPU name and both TF32 flags, plus `torch_num_threads`, `worker_count` and `device_index` as **provenance only** (:980–984). `REPLAY_REFUSAL_KEYS` (:952–965) names exactly the first seven as refusal keys; the comment at :954–956 explains the exclusion of `worker_count`/`device_index` as a fix for a proven deadlock (worker-count-in-key composed with single-worker replay). Consumed at :3942–3945.
- `make_schedule_id(cfg)` (line 1534) — SHA-256 of the literal `"uniform-no-replacement|{window!r}|{fans_per_episode}"`. Both inputs are frozen fields, so this is a human-legible grouping label derivable from the frozen block, not an independent identity; it is stamped on every fan record (:2367, :2396, :2452, :2483, :2991, :3172, :3447, :3599) and pinned in the freeze manifest (:2882).
- `_git_rev()` (line 2829) / `_worktree_clean()` (line 2835) — `git rev-parse HEAD` and `git status --porcelain == ""`, both `check=True`. They bind the artifact chain: `freeze_manifest` refuses on a dirty worktree (:2863) and refuses unless live `HEAD` equals the `git_rev` inside `certified.json` (:2869–2871), which `--selftest --certify` writes via an atomic `os.replace` (:2298–2300). `_git_rev()` is also the sole `env` payload on preflight-summary and policy-training records (:2999, :3455).

**Patterns Observed:**
- **Two orthogonal identity hashes, by construction.** `config_hash` covers code text; `frozen_block_hash` covers pre-registered parameter values. Neither subsumes the other, and :3948–3952 documents the exact gap that would open if the second were dropped — the failure would not be missed, it would be *misattributed*.
- **Import-time-only registration.** Both `semantic` (:61–63) and `semantic_const` (:76–77) carry the same prohibition against call-time registration, traced to a named historical defect. `config_hash` then sorts both streams (:233, :235) so the digest is order-independent even if registration order changed.
- **Refuse rather than tolerate.** `enable_class1` raises on a stray `CUBLAS_WORKSPACE_CONFIG` instead of overwriting it (:922–924); `semantic_const` raises on a duplicate name (:81–82); `freeze_manifest` raises on a dirty worktree or a HEAD/certified mismatch (:2863–2871); every mode entry point re-checks both hashes before doing work (:3149–3152, :3343, :3463, :3946–3952).
- **Fail-closed comparison.** The replay env check (:3943) compares `rec.env.get(k) != live_env.get(k)`, so a record carrying only `{"git_rev": …}` (:2999, :3455) reads `None` for all seven refusal keys and is refused rather than admitted.
- **Determinism by avoiding the global stream, not by seeding it.** `torch.manual_seed` is never called anywhere in the file; instead every draw either takes an explicit `generator=` or runs inside `rng_scope`. **Verified**, not assumed: the only unscoped `torch.randn` in production code (:1717) sits inside `with rng_scope(gen):` opened at :1715. `rng_scope` is exception-safe via `try/finally` (:129–133) and every call site passes a freshly built generator (:629, :730, :1715), so the write-back at :132 cannot cause cross-call drift.
- **Provenance/refusal is a deliberate two-tier split.** `env_block` returns ten facts; `REPLAY_REFUSAL_KEYS` promotes exactly seven. Each demotion carries a written reason at the point of exclusion (:954–956, :980–982) rather than being silent.
- **Self-classification is enforced out-of-band.** `tests/unit/kernel_demo/test_derive.py:93` walks `vars(k)` and fails on any unclassified public class/function, so the `@semantic`-by-default rule is a gate rather than a convention — for classes and functions (see Concerns for what it does not reach).
- **Narrative-order placement.** The determinism block sits at :917–989 rather than beside identity at :44–251, following the module docstring's declared 17-section reading order (:10–27). Per spec rev 6.1 this single-file, read-top-to-bottom layout is by design, not debt.

**Concerns:**
- **`d_model` (:176) and `n_layers` (:177) are outside `FROZEN_FIELDS` (:188–223) although the author's own stated freezing criterion covers them.** :180–183 admits `batch_size` and `run_seed` to the frozen block precisely because they are "trajectory-defining … and no other hash covers them". `d_model` and `n_layers` define the policy transformer's architecture (:1714, :1718) and satisfy the same test, yet an edit to either moves neither hash — `Config` is `_NON_SEMANTIC` (:91) and `Policy`'s source text is unchanged. Mitigation is partial and indirect: `ckpt_id = state_hash(policy)` (:3364) captures the shape via the state dict, so a `--train`/`--eval` mismatch would surface as a different checkpoint id; but nothing *refuses*, and the comment at :3362 ("d_model=64; the env pins make any numerics drift refusable") asserts coverage the env pins do not actually provide for an architecture change. Severity: moderate.
- **`FROZEN_FIELDS` is a hand-maintained list parallel to `Config`, with no completeness test.** Nothing asserts that every `Config` field is either frozen or on a documented lever list; `test_derive.py:44–51` spot-checks four frozen fields plus `n_collect`. A field added to `Config` in a future edit lands outside the frozen block silently. This is the same class of gap that `test_every_public_symbol_is_classified` closes for classes and functions — the config-field analogue is simply absent.
- **The classification test cannot reach module constants.** `test_derive.py:100` filters to `inspect.isclass or inspect.isfunction`, so a new behaviour-changing module constant that its author forgets to wrap in `semantic_const` is covered by no gate at all. The existing constants are correctly reasoned about at :76–80, but by discipline, not enforcement.
- **`_git_rev` (:2829) and `_worktree_clean` (:2835) are certification-gate primitives that are neither hashed nor classified.** `test_derive.py:99` skips names starting with `_`, and neither carries `@semantic`, so neither appears in `config_hash`. Concretely: adding `--untracked-files=no` to the argv at :2838 would materially weaken the freeze gate while moving no hash and failing no test. The underscore boundary is also inconsistent — `_sanitize_json` (:1547) *is* `@semantic` despite the same prefix — so "private means non-semantic" is not a rule a reader can rely on.
- **`enable_class1()` is enforced by comment, not mechanism.** :918 states it "MUST be the first statement of every process". It is honoured at both process entry points (`main` :4005, `worker_main` :3077) and in the selftest paths (:2088, :2258), but there is no import-time call and no runtime assertion. Any consumer that *imports* the module rather than running the CLI therefore exercises semantic functions with the Class-1 knobs unset — that includes `kernel_demo_plots.py` and every test module in `tests/unit/kernel_demo/` except `test_determinism.py`. The same enforcement-by-convention shape appears in `FORBIDDEN_RELAXATIONS` (:900–913), which :901–903 explicitly designates documentation-only: "enabling AMP" and "torch.compile" are listed as voiding the Class-1 claim, and nothing checks for either.
- **CPU thread count is recorded but not controlled and not refused on.** `torch.set_num_threads` is never called; :980–982 records `torch_num_threads` and states plainly that CPU GEMM reductions are thread-count dependent and that policy training runs on CPU (:3360) — then places it outside `REPLAY_REFUSAL_KEYS`. Scope of the exposure is bounded: `--replay` accepts only `kind='fan'` records (:3957) and fans run on `device`, so the bitwise-replay claim for fans stands. What it bounds is the *policy-training* leg — that leg is reproducible only on a host with the same thread count, and nothing will tell you when it is not.
- **The "no unscoped draw" invariant is enforced by one text needle in three sections.** Selftest check 6 (:2159–2163) greps `_section_source(4|5|11)` for the literal `nn.init.`. It would not catch `torch.randn(...)` / `torch.rand` / `torch.randperm` without `generator=`, an in-place `.normal_()`, or an `nn.init.` call in any other section. The invariant holds today (verified above at :1715–1717), so this is a regression-surface concern rather than a live defect — but it is the weakest link in an otherwise mechanically-enforced spine.
- **`state_hash` hashes bytes without dtype or shape (:938–944).** The digest covers the parameter name, byte length and raw bytes only; two state dicts differing only in a shape or dtype reinterpretation that preserves per-tensor byte length would collide. Unlikely to fire under a fixed architecture, and the D8 zero-normalization it does implement is correct and tested (`test_determinism.py:27–34`), but the exclusion is undocumented. Separately, `.numpy()` (:941) would raise on a bfloat16 parameter — safe only because AMP is banned, and that ban is documentation-only (see above).
- **The module docstring cites a superseded spec revision.** :8 reads "Spec (LOCKED, rev 6)", while `freeze_manifest` stamps `"rev6.1 (98083fd + 2026-08-10 pre-data amendment: episode-level money null + falsifier CI)"` at :2877. The manifest is right and the docstring is stale; the docstring is the first thing a reader of this single-file demo encounters.
- **`derive` stringifies labels (:105), so an int label collides with its string form** — `derive(s, 1)` and `derive(s, "1")` are identical. Mixed int/str label tuples are common (:1020, :2937, :3286). No current call-site pair collides, since every tuple is prefixed by a distinct string namespace, but the property is undocumented. Severity: low.

## Data, Episodes & Telemetry

**Location:** `experiments/kernel_demo.py` (lines 252–554, 990–1141)

**Responsibility:** Supplies the deterministic CIFAR-10 split, the pre-drawn shared augmentation schedule that makes compared arms matched, the blind per-epoch telemetry record and its feature vector, and the single-epoch training/evaluation step that produces them.

**Key Components:**
- `DataBundle` (line 252) - Flat six-tensor carrier for train/val/test `x`/`y`; all six are moved to the compute device in `load_data` (lines 296–303), including the 10,000-image test set, regardless of whether the caller intends to read it.
- `split_indices` (line 262) - Derives the 45,000/5,000 train/val partition as `torch.randperm(50_000)` under `make_generator(derive(run_seed, "valsplit"))` (line 263). Fully deterministic from `cfg.run_seed`; disjoint by construction as a partition of one permutation. Test is the official CIFAR-10 test split (`train=False`, line 284), never drawn from the 50,000. Selftest `partition_check` (lines 2224–2231) independently asserts sizes 45k/5k and `torch.isin` non-overlap. **No leakage between the three splits.**
- `data_split_id` (line 268) - SHA-256 over length-prefixed `train_idx`/`val_idx` index bytes (lines 271–275). Identifies *which* partition, not *what data*. Consumed by `freeze_manifest` (line 2883) and enforced as a replay refusal (line 3955).
- `load_data` (line 279) - Deferred `import torchvision` (line 280) so the module imports without it; `download=True` against hardcoded `root = "runs/data"` (lines 282–284). `subset` truncates `train_idx` only (lines 288–289), leaving val and test at full size.
- `CommonFuture` (line 308) + `draw` (line 316) - **Common random numbers, verified by construction, not by name.** All per-step stochasticity for a whole episode is pre-drawn up front from one generator: batch `order` per epoch, `crops` in `[0,9)`, and `flips` (lines 322–324), plus a SHA-256 `hash` (lines 325–328). `make_episode` draws exactly one instance (line 1020) and the *same object* is threaded to every arm — `run_fan` passes it to the noop arm (line 1381), each seed arm (line 1392) and the nullseed arm (line 1402), received as the `future` parameter of `run_arm` (line 1291). Arms therefore see byte-identical data order and augmentation. `run_refan` deliberately draws a *different* future under a distinct label tuple (line 2469) to supply the gate-3 noise floor. `draw` refuses a subset too small to form one step (lines 320–321).
- `augment` (line 332) - Normalize → reflect-pad 4 → gather the crop window by advanced indexing → conditional horizontal flip (lines 334–343). Consumes the pre-drawn `crops`/`flips` slices; draws no randomness itself.
- `TelemetryDivergence` (line 347) - Raised only from `TelemetryRecord.__post_init__` (lines 375, 379) when any float field is NaN or ±inf. It guards the *record construction boundary*, so a numerically diverged epoch cannot enter telemetry, the store, or the policy's feature stream. Caught by the fan executor (line 1256), `run_refan` (line 2437) and `run_eval` (lines 3518, 3583), which convert it into a recorded void/diverged outcome rather than a crash. Registered `_NON_SEMANTIC` (line 504) so its source is excluded from `config_hash`.
- `TelemetryRecord` (line 357) - **Blinding is by ABSENCE of fields, not by ignoring them.** Field-by-field, lines 358–369 are: `epoch`, `train_loss`, `val_loss`, `val_acc`, two loss deltas, and four per-stage triples (`grad_norm_mean`, `grad_norm_var`, `act_saturation`, `weight_norm`), `per_class_val_acc_std`, `confusion_entropy`. There is **no** seed name, arm name, pathology id, episode seed, or provenance field anywhere in the dataclass — the identity is not present to be ignored. `frozen=True` prevents post-construction mutation.
- `record_to_vector` (line 397) - Maps exactly those 20 fields to a `TELEMETRY_DIM`-20 float32 vector (lines 398–420). No identity or provenance enters the feature vector; `epoch` (index 0, `EPOCH_FEATURE_IDX` line 352) is the only non-metric feature and carries no arm/seed information. **No leakage of identity into features.**
- `confusion_stats` (line 424) - Builds a 10×10 confusion matrix by explicit double loop (lines 428–434) and returns two scalars: the standard deviation of per-class accuracy (line 438) and the Shannon entropy of the normalized *off-diagonal* (error) mass (lines 439–446), with an explicit `0.0` when there are no errors.
- `Normalizer` (line 451) - Median/IQR feature scaler. Default construction is the identity transform (zeros/ones, lines 456–463); `fit` computes per-dimension median and clamped IQR (lines 465–471). **Fit on preflight material only, then frozen.** The single `fit` call site is `run_preflight` (lines 2958–2961) over telemetry of `seed_namespace == "preflight"` fans only (line 2957); the result is serialized into `frozen.json` (line 2878) and thereafter loaded read-only via `from_json` by `run_train` (line 3347) and `run_eval` (line 3493). Preflight episodes run `read_test=False` (line 2941), and telemetry contains only train/val-derived quantities, so **the normalizer never sees test material and is frozen before any training or evaluation** — no calibration-on-test.
- `build_record` (line 508) - Keyword-only pass-through constructor (lines 522–535). Adds no fields, so it cannot widen the blind surface; it also performs no numeric coercion, delegating all validation to `__post_init__`.
- `normalize_u8` (line 990) - Eval-path normalization: same mean/std as `augment`, no crop/flip (lines 991–994).
- `EpisodeCtx` (line 999) - Episode state: config, the shared `DataBundle`, device, `episode_seed`, derived `pathology`, the `CommonFuture`, live `host`/`opt`/`slot`, the accumulating `telemetry` list, `curves_val`, and `curves_test` typed `list[float] | None` — `None` iff `read_test=False`, an explicit convention against empty-list ambiguity (line 1011).
- `make_episode` (line 1016) - Derives everything from `episode_seed` via labelled derivation: pathology (line 1017), host init (line 1018), and the future (line 1020). `read_test` defaults to `False` (line 1016).
- `evaluate_acc` (line 1041) - Chunked accuracy under `no_grad`; captures and restores the prior `training` flag for *both* host and slot (lines 1042, 1052–1053).
- `train_one_epoch` (line 1058) - The episode's unit of work. **Draws no RNG:** batch order, crops and flips are all indexed out of `ctx.future` (lines 1060, 1069), so the function issues no new random draws — the global stream still matters for any module-internal stochastic op, which is why `Snapshot` carries `cpu_rng` (line 1149). Per-step it augments, forwards, adds `slot.trust_region_loss`, backprops, accumulates per-stage gradient norms (lines 1076–1081), steps, and ticks the slot. It then evaluates the full val split under `no_grad` (lines 1094–1106), assembles the record (lines 1119–1132) and appends to `telemetry`/`curves_val`.

**Dependencies:**
- Inbound: Counterfactual Fan Executor `[call]`; Policy & Learning `[call + serialized-shape]`; Certification Battery `[call]`; Run Orchestration & CLI `[call]`
- Outbound: Identity, Config & Determinism Spine `[call]`; Host, Seeds & Slot Lifecycle `[call]`

**Patterns Observed:**

**Patterns Observed:**
- **Uniform delta contract, verified empirically.** All four seeds take `channels: int`, map `[B,64,8,8] → [B,64,8,8]`, and produce an exactly-zero delta at construction (`gain=0`). After `tau_init` all four land at `rms(gain*f(h))/rms(h) = 0.0500` — exactly `cfg.tau` — despite `rms(f0)` differing by orders of magnitude across seeds (measured g: 0.9215 / 0.3307 / 0.1187 / 0.04998). The τ-normalization is what makes structurally dissimilar seeds enter on a common scale.
- **The seed is NOT a no-op at germination — the STE is.** `germinate` (:1181) tau-inits `gain` to a *nonzero* value, then `Slot.forward` (:819) returns `h + (delta - delta.detach())` during `TRAINING`: the forward value is bitwise `h`, while the seed still receives full gradients. The no-op property is provided by the estimator, not by a zero gain. Verified: `torch.equal(h + (d - d.detach()), h)` is True for finite `d`.
- **α and β gate different things, and β is specifically *upstream*.** α (:820) scales the delta into the forward value; β (:814) interpolates `hin` between `h.detach()` and `h`, controlling gradient flow *back into stage1/stage2 through the delta branch*. Measured: extra upstream gradient beyond the identity path is **exactly 0.000000 at β=0 in every stage**, and scales ~linearly with β (0 → ~400 → ~800 at β=0/0.5/1.0). Since β only ramps in `FOSSILIZING` (:850), the host is gradient-isolated from the seed branch for the whole of TRAINING and BLENDING.
- **Lifecycle trace.** DORMANT →(`germinate`, :1184, skipping GERMINATED)→ TRAINING (`stage_k`=3 epochs; STE, α unused, β=0, trust region active) → BLENDING (`stage_m`=3; α cosine-ramps 0→1 per step, forced to 1.0 at exit :865) → FOSSILIZING (`stage_f`=2; β cosine-ramps 0→1) → FOSSILIZED (α=β=1, :867–869). Transitions are epoch-granular, ramps step-granular.
- **The trust region exists precisely because the STE hides the delta.** `trust_region_loss` (:827) is `λ·mean(δ²)/mean(h.detach()²)` and self-gates to `TRAINING` only (:825). Under STE the CE loss cannot constrain δ's magnitude at all (forward value is `h` regardless), so this relative-magnitude penalty is the only thing bounding δ before α turns up. `λ=1.0` is documented as inside the stability bound `λ < 1/seed_lr ≈ 20` (:823).
- **The classic add-param-group bug is anticipated and structurally designed out.** The comment at :874–878 names it: `lr_scheduler` captures `base_lrs` positionally at construction, so a group appended at germination would mismatch — constant LR removes the class rather than patching it. Verified empirically: `add_param_group` preserves existing momentum buffers exactly (state is keyed by parameter object, not group index), new params correctly start with no state (fresh momentum), and the new groups inherit `momentum=0.9`/`nesterov=True` from `defaults` while overriding `lr`/`weight_decay`. **No corruption of existing momentum or LR.**
- **Double-germination is refused, not tolerated.** `germinate` (:1169–1173) raises unless the slot is `DORMANT`, explicitly to prevent duplicate optimizer groups silently orphaning a prior seed.
- **Parameter ownership is partitioned by construction, not by filtering.** `Slot` is never a submodule of `Host` (verified: `any(m is slot for m in host.modules())` is False; seed params absent from both `host.named_parameters()` and `host.state_dict()`). - **Decay partition is total and correctly typed.** `ndim <= 1` catches biases and all norm affines even under `nn.Sequential`'s integer names, where substring rules would mis-file BN affines (:754–756). Every parameter reaches exactly one group; nothing is dropped from the optimizer.

## Counterfactual Fan Executor

**Location:** `experiments/kernel_demo.py` (lines 1142–1419)

**Responsibility:** Runs the demo's scientific core — from one snapshot of a single
base training pass, it re-materialises N independent arms (a measured no-op plus each
candidate seed) over identical future data, verifies bitwise that the arms are genuinely
matched, and reduces each arm's validation curve to a scalar reward.

**Key Components:**
- `Snapshot` (line 1142) - dataclass capturing exactly five fields: `host_state`
  (full `state_dict`, params + BN buffers), `opt_state`, `cpu_rng`, `cuda_rng`,
  `epoch`. Comment (1143–1146) states the invariant that makes this sufficient:
  snapshots are taken only on the base path, where the optimizer is always the
  never-germinated 2-group state, and there is deliberately no `restore_snapshot`.
- `take_snapshot` (line 1155) - clones host state (`.detach().clone()`, 1158),
  `copy.deepcopy`s optimizer state (1159), captures global CPU RNG (1160) and the
  device-specific CUDA RNG only when the device is CUDA (1161). `epoch` is derived
  as `len(ctx.telemetry)` (1162), not passed in.
- `germinate` (line 1167) - the single sanctioned influence-raising path. Refuses
  unless the slot is `DORMANT` (1169–1173, guarding against duplicate optimizer param
  groups and a silently orphaned seed); builds the seed under
  `derive(episode_seed, "arm", seed_name)` (1174); measures host features under
  `host.eval()` + `no_grad` with a *fixed* val batch (1176–1180) so tau calibration
  cannot touch host BN statistics; runs `tau_init`, appends the seed's optimizer
  groups, sets `Stage.TRAINING` directly (GERMINATED is zero-duration, 1184).
  Returns the tau gain `g`.
- `end_state_R` (line 1189) - reward = arithmetic mean of the **last three** curve
  entries (1192), i.e. a 3-epoch trailing window, not a single end-state value.
  Hard-fails with `ValueError` if the curve has fewer than 3 entries (1190–1191).
- `TwinDivergence` (line 1196) - harness-integrity exception carrying
  `first_bad_epoch` in **absolute** episode epoch numbering, not an offset from
  `snap.epoch` (1198–1201). Registered as non-semantic (1204).
- `ArmResult` (line 1209) - per-arm result: status, `r_val`/`r_test`, curves,
  `init_seed` provenance, `g_at_init`, `rms_ratio_blend_entry`,
  `hash_after_training` (every arm), `host_hashes` (noop/nullseed only, 1220),
  `alpha_beta_log`.
- `BaseTrace` (line 1226) - base-pass result carrying `host_hashes`, curves,
  `snapshots` keyed by fan epoch (1230), status and `diverged_at`.
- `_run_span` (line 1236) - THE inner epoch loop, deliberately the single
  implementation shared by base and arms so "base/twin drift is structurally
  impossible" (1243–1245). Snapshots are taken *before* the fan epoch trains
  (1252–1253), which is what aligns an arm's hash list with
  `base.host_hashes[snap.epoch:]`. Catches `TelemetryDivergence` and converts it to
  `status="diverged"` + `diverged_at` (1256–1259).
- `run_base` (line 1268) - one pass over `range(0, horizon)` collecting per-epoch
  host hashes and the scheduled snapshots (1273).
- `run_arm` (line 1285) - "arm-local materialization" (1296–1297): builds a **fresh**
  `Host` (1298), re-attaches stat hooks (1299), `load_state_dict` from the snapshot
  (1300), fresh `Slot` (1301), fresh 2-group optimizer (1302), then loads a
  `deepcopy` of the optimizer state (1306), then restores global CPU/CUDA RNG
  (1307–1309). Dispatches on `arm_name` into seed / `nullseed` / `noop` (1326–1338).
- `run_fan` (line 1367) - orchestrates the fan: twin first (1381), twin hash
  comparison against the base tail (1382–1388), then each seed arm (1391–1392), then
  the cross-arm post-TRAINING bitwise check (1396–1400), then the optional null-seed
  arm with its hard-stop value-exactness check (1401–1415).

**Dependencies:**
- Inbound: Run Orchestration & CLI (calls `run_base` :2343, `run_fan` :2355 and
  :3980, and calls `germinate`/`end_state_R` directly on the eval-comparator path

**Patterns Observed:**
- **Rebuild-not-restore.** No `restore_snapshot` exists (1145–1146). Every arm is
  constructed fresh and loaded from snapshot *values*, so cross-arm state leakage is
  prevented by construction rather than by discipline (1296–1297). Verified: the
  snapshot's own tensors are protected — host tensors were cloned at capture (1158)
  and `load_state_dict` copies into the destination, and the optimizer state is
  `deepcopy`d again at load (1306) so in-place momentum updates cannot reach `snap`
  (comment 1305).
- **Common random numbers enforced by data structure, not by re-seeding.** `future`
  is a `CommonFuture` of *precomputed* tensors drawn once per episode
  (`CommonFuture.draw`, :316–328, called at :1020) and passed by reference into every
  arm (1291 → 1316). `train_one_epoch` indexes it by **absolute** epoch —
  `ctx.future.order[epoch]` (:1060), `crops[epoch, s]`, `flips[epoch, s]` (:1069) —
  and arms iterate `range(snap.epoch, horizon)` (1251, 1339). Arm epoch *e*
  therefore consumes byte-identical batch order, crops and flips as base epoch *e*.
  There is no sampler to desynchronise, which is why "dataloader position" is absent
  from `Snapshot` without being a gap.
- **Arm identity is isolated from the shared RNG stream.** All arms restore the
  *same* `snap.cpu_rng` (1307) — the per-arm seed is **not** re-derived from arm
  identity for the global stream. Arm identity enters only via
  `derive(episode_seed, "arm", seed_name)` (1174) handed to `build_seed`, which
  constructs under `rng_scope(make_generator(...))` (:730). `rng_scope` (:123–133)
  saves and restores the process-global state, so a seed class drawing more
  parameters than another cannot shift the shared stream. This is the mechanism that
  makes the cross-arm bitwise assertion at 1398–1400 achievable at all.
- **The no-op is a real measured arm, not an assumed zero.** `run_fan` executes
  `"noop"` through the identical `run_arm` → `_run_span` → `train_one_epoch` path
  (1381), its reward comes from `end_state_R(ctx.curves_val)` (1341), and it is the
  first element of the returned `arms` list (1390). It is measured *and* doubles as
  the harness twin.
- **Twin-first ordering as an economic guard.** The twin runs before any seed arm so
  a broken harness fails the fan before compute is spent (1379–1380).
- **Three graded integrity instruments, deliberately differentiated.** (a) Twin hash
  equality vs the base tail → `TwinDivergence` (1384–1388); (b) cross-arm
  post-TRAINING host-hash equality → bare `assert` (1398–1400); (c) null-seed exact
  reproduction of the base, *including mirroring a base divergence at the same
  epoch* → unconditional `RuntimeError` with an explicit "no weaker fallback, curves
  are never a comparand" comment (1404–1414).
- **Failure is typed and non-collapsing.** A telemetry failure inside an arm becomes
  `status="diverged"` + the sentinel `cfg.diverged_r` (1343–1345), which is a
  *result*; a harness failure becomes an exception that aborts the fan. The null-seed
  comment (1407–1409) explicitly forbids downgrading instrument failure into an
  ordinary diverged-arm record.
- **Provenance names the stream actually drawn from.** `init_seed` for the
  `nullseed` arm records `conv_light`'s derivation, not a fictional `"nullseed"`
  stream, because that is the generator the module was really built from
  (1354–1357).
- **Zero-normalized hashing is load-bearing here.** During TRAINING the slot returns
  `h + (delta - delta.detach())` (:819). For finite `h` this is value-identical but
  maps `-0.0 → +0.0`, so the arms' hosts are bitwise-equal only under
  `state_hash`'s zero normalization (:934–940, "D8"). The fan's value-exactness
  assertions depend on that normalization existing.
- **Constant LR removes a whole snapshot field.** `build_optimizer`'s comment
  (:874–878) records that constant LR is load-bearing twice — no scheduler state to
  snapshot, and no positional `base_lrs` mismatch when a group is appended at
  germination. Verified: `Snapshot` carries no scheduler state and none is needed.
- **Optimizer group ordering is a matching invariant.** Seed groups are *appended*
  as groups 2/3 (:892–896) after the 2-group host state is loaded (1303–1306), so
  host groups 0/1 keep identical identity and iteration order across every arm.

**Concerns:**
- **The cross-arm value-exactness check is a bare `assert` and silently no-ops near
  the horizon.** Line 1400 uses `assert`, which is stripped under `python -O` —
  unlike the null-seed check (1411) which correctly raises. Worse, the loop at
  1398–1400 is guarded by `twin_hash_at is not None` and

  (1339, 1396–1397) both are `None` and the demo's central matching assertion

- **The reward is named "end state" but is a 3-epoch trailing mean** (1189–1192).

- **Snapshot RNG capture covers only torch's CPU and CUDA generators** (1160–1161) —

- **`meta` is a bare `dict[str, object]`** (1389, 1415) with keys set only on

**Patterns Observed:**

- **Content-addressed identity over counters.** `fan_identity` (:1459) hashes the full identity tuple, so a resumed run reconstructs identical ids and re-collection is idempotent. The comment at :1498–1500 names the rule explicitly: `iteration` and `policy_checkpoint_id` must come from store state or content identity. Call sites honour it — `iteration=len(ext_events)` (:3174) and `iteration=len([...void_event])` (:3448) are both derived from a `merge()` of the store, never a process counter.
- **Split decided once, at collection time, and recorded.** `train_tune_split` (:1540) is a pure function of `episode_seed` via `derive`; the call site at :2339 stamps it onto the episode before any fan is produced, and every fan of that episode inherits the same `split_role` (:2367). **The grouped-statistics hazard is closed:** one base trajectory cannot straddle train and tune, because the split is a function of episode identity rather than arrival order or record identity, and it is never recomputed downstream (`load_for_training` :1674 and the tune filter at :1946 read the recorded field). The `refan` path never assigns train/tune at all — it hardcodes `"preflight" if namespace == "preflight" else "eval"` (:2447, :2478), so refans cannot leak into training.
- **Fail-closed schema versioning.** `decode_record` (:1567) raises on any `schema_version` inequality rather than attempting migration, and the error text (:1569–1572) states the governing policy: additive-only post-collection, non-additive bumps are an owner decision, "never silent."
- **Non-finite encoded as `null`, and the null is loud downstream.** `_sanitize_json` (:1550–1551) maps NaN/Inf to `null` rather than emitting JSON's non-standard `NaN` literal. The lossiness is deliberately paired with `_as_float` (:1802–1807), which raises on `None` and on any non-numeric — so a serialized non-finite reaching the numeric path raises rather than silently becoming zero. Round-trip is directly tested (selftest :2194–2199; `tests/unit/kernel_demo/test_store.py:66`). **Float precision is preserved exactly:** `json.dumps` serializes floats via `float.__repr__` (shortest round-tripping repr), not a fixed format.
- **Torn-final-line tolerance is real and correct for the simple case.** `merge()` (:1617–1629) catches `JSONDecodeError`, and if the bad line is the file's last it prints a loud warning and continues; only an *interior* bad line re-raises. The stated rationale (:1622–1626) is that a torn final line is a host crash mid-append whose record was never durable, i.e. the ≤`fsync_every` contract operating as designed rather than corruption. **Verified by execution:** a store torn mid-record merges to exactly its prior records with a warning. `test_store.py:98` covers both halves of this.
- **Single-record appends are atomic against concurrent writers.** Mode `"a"` (:1595) sets `O_APPEND` (verified), and the flush-on-every-append at :1599 keeps the buffer empty so each record leaves Python as exactly **one** `write()` syscall — measured as 1 raw call for payloads of 14 KB, 1 MB, and 10 MB, with no partial writes. On Linux + ext4 the kernel holds the inode lock across a buffered regular-file write, so `O_APPEND` position-and-content are atomic together. **Verified empirically:** 8 concurrent processes × 300 appends of 14 KB records into one shard produced 2,400/2,400 valid, distinct lines and zero malformed lines.
- **Shard-per-writer as the concurrency strategy.** `run_collect` assigns each spawned process a unique `wid` from `enumerate(slots)` (:3225), gives it a disjoint seed slice `todo[wid::len(slots)]` (:3226), and has the parent call `store.close()` (:3216) *before* spawning. Within one invocation the scheme is sound.
- **Canonical merged order, independent of write order.** `merge()` sorts on a 7-tuple (:1646–1655) with `None`-coalescing to `-1` and trailing discriminators (`policy_checkpoint_id`, `iteration`, `fan_id`) chosen so that kinds the leading key cannot separate still order deterministically. The comment at :1644–1645 states the invariant: "shard-file/append order must never leak into consumers."
- **Duplicate detection as a hard stop.** `merge()` (:1633–1639) raises `ValueError` on a repeated `(manifest_hash, fan_id)` for `fan`/`refan`. Exercised by appending the same record to two shards (selftest :2210–2215; `test_store.py:90`).
- **Graded durability with a stated target.** Flush on every append (:1599) — process crash loses nothing; `os.fsync` every `fsync_every` records (:1601–1602, default 20 at :179) — host crash loses ≤ 20. `close()` (:1604–1610) flushes and fsyncs every handle. Correct ordering (Python buffer flush before `fsync`).
- **Typed, asymmetric split wall.** `_assert_trainable` (:1664) distinguishes two violations with distinct messages — an eval-split record on the training path (:1667) and a wrong-kind record (:1669) — rather than one generic assert. Tested on the yield path (`test_store.py:133`).
- **Vocabulary-driven validation with no escape hatch.** All three whitelists (:1426–1428) are checked in the sole constructor, so an invalid record cannot be built, let alone written.
- **Clean one-way dependency: the persistence layer is a verified leaf.** Records & Store depends on exactly one other subsystem — the identity/config spine — and on nothing else in the file; six of the seven other subsystems depend on *it*. Established mechanically rather than by reading declarations: an AST pass over every `Name` load in 1420–1681 resolves to `semantic`, `_NON_SEMANTIC`, `SCHEMA_VERSION`, `derive` and `Config`, and a second pass over every attribute access finds no read of any foreign shape. This is the property you would design for and rarely get — the layer that defines the on-disk contract is not entangled with the producers or consumers of the data it carries, so the schema can be reasoned about, versioned, and tested in isolation (as `test_store.py` in fact does, with no fan, host, or policy fixtures). Worth stating positively, because the same structure in the parent programme's terms is a dependency-direction rule: contracts import nothing from the subsystems that use them. **The isolation is achieved but not enforced** — the single-file layout (a locked spec decision, so by design) means there is no module boundary or import gate to keep it true, and no linter would catch a future edit that reached from this range into the fan or telemetry sections. It holds by discipline, and it currently holds completely.
- **Deliberate payload opacity.** `arms` and `telemetry` are declared `list[dict[str, object]]` (:1451–1452) and the store never inspects them: an AST inventory of every attribute access in the range finds zero field-name reads of any payload shape. The whitelists validate the record's *envelope* — kind, namespace, split role — and nothing validates its *contents*. This is coherent with the store's job and is why it takes no dependency on the sections that produce the payloads; the cost is in the next bullet.

**Concerns:**

- **A record written after a torn tail is silently lost, behind a warning that is byte-identical to the benign case.** This is the section's most serious defect and it is a silent-loss bug, not merely an availability one. `append` opens mode `"a"` (:1595) and writes the newline as a *suffix* (:1598), so a partial line carries no terminator and the next append fuses onto it. **Reproduced end to end against the real `Store`:** (A) tear a shard mid-record → `merge()` returns the 2 prior records with the warning, correct; (B) resume and append a third record → the file still has 3 lines, the new record having fused into the partial one; (C) `merge()` returns **2 records — the record just written is gone**, behind the identical `"skipping torn final line"` message from :1627, indistinguishable from (A); (D) one further append makes the fused line interior → `merge()` raises → the store is unreadable by every consumer. The apparent mitigation is the trigger: the lost `fan_id` is absent from the `merge()`-derived skip set (:3157), so collection re-runs it — and that re-collection append is exactly step (D). `test_store.py:98` covers (A) and a hand-built interior tear, but **never appends after a tear**, so (B)–(D) are untested. Fix is one line at shard open: seek to the last newline and `truncate()`, or write the newline as a prefix.
- **Severity note — validity is protected, availability is not.** The blast radius of the above stops short of a wrong published number. A pre-existing torn tail crashes `run_preflight` at its very first `store.merge()` (:2922–2923) *before any gate runs*, so freeze is fail-closed against it; and `run_eval` refuses on an episode-count shortfall (:3491–3492, `"eval refused: incomplete collection"`), so a quietly-dropped episode cannot silently shrink the eval population. The cost is a bricked collection run and its compute, plus operator confusion — not a corrupted result. That distinction should survive into the final report.
- **Interior corruption escapes as an untyped `json.JSONDecodeError`.** The re-raise at :1629 propagates the raw decode error out of `merge()`. Every other failure mode in this file has a named class (`SplitViolation` :1420, and `TelemetryDivergence` / `TwinDivergence` elsewhere), and `test_store.py:104` only passes because `JSONDecodeError` subclasses `ValueError`. Store corruption is a distinct operational condition and deserves a distinct class, consistent with the module's own typed-failure discipline.
- **No writer exclusion on shard files — but the failure is loud, not silent.** There is no lockfile, PID guard, or `O_EXCL` anywhere in the module (verified by negative grep). Two concurrent `--collect` invocations against one store root each start `wid` at 0 (:3225) and write into the same shard. Having established that appends are line-atomic, the outcome is **duplicate-but-valid records, not malformed lines** — so the first thing to fire is `merge()`'s duplication backstop at :1638 (`ValueError: duplicate fan_id`), the designed refusal working exactly as intended. The store still becomes unreadable until the duplicate lines are removed, but this is a tractable, typed, loud failure rather than byte-level corruption. Downgraded accordingly; a store-root lockfile remains the cheap fix, and the atomicity guarantee should be written down as a load-bearing assumption since it is platform-scoped (Linux + local ext4; **NFS `O_APPEND` does not provide it**).
- **Payload opacity makes the store a silent conduit for shape drift.** Because nothing between producer and consumer inspects the payload, two different `arms` shapes travel the same pipe undetected: the full 12-field `ArmResult` via `dataclasses.asdict` (:2376, :2492) and hand-built partial dicts of four or five keys (`:2188` — `name`/`status`/`r_val`/`curve_val`; `:3608` — `name`/`status`/`r_val`/`r_test`). Consumers read fields by name off the merged result (:1845, :2511, :2517) and would raise `KeyError` on the wrong shape, at read time, against data already durable on disk. The store cannot catch this by design, but it is the component through which the drift flows, and the envelope/contents asymmetry above is exactly the gap: `RECORD_KINDS` is enforced, arm shape is not. A `kind`-conditional payload check in `make_fan_record` would close it at write time. Note for the dependency matrix: these `serialized-shape` edges run **producer → consumer** and pass *through* Records & Store without touching it — renaming `ArmResult.r_val` breaks Policy & Learning and the Certification Battery while leaving this section entirely unaffected, so routing them as store-adjacent edges would misattribute the change impact.
- **`decode_record` is a tolerant reader with no current beneficiary.** `kwargs = {f.name: data.get(f.name) for f in dataclasses.fields(FanRecord)}` (:1574) fills any absent field with `None` at the *same* `schema_version`. `SCHEMA_VERSION = 1` (:55) means there are zero additive-evolution cases today, so the tolerance is currently pure hazard: a field-dropping record decodes without complaint, and a `None` `split_role` would drop it from the training filter (:1674) silently, while a `None` `episode_seed` would surface only as a `TypeError` in the sort key (:1648). Mitigated but not closed by `_as_float`'s loud `None` handling (:1802–1807), which covers the numeric path only. A required-field non-`None` check after construction would close it.
- **A skipped torn record leaves only a stdout `print`, not a record.** The warning at :1627 goes to stdout with `flush=True`. In a store whose stated premise is complete append-only history — `void_event` exists precisely so failures stay on the record (:2383, :2442) — a lost record that survives only in a console log is a coherence gap with the design's own discipline, and it is what makes the silent-loss step above so hard to notice.
- **`manifest_hash` is in the dedup key but not in any read filter.** `merge()` keys collisions on `(manifest_hash, fan_id)` (:1636), deliberately permitting the same fan under two freeze generations (comment :1630–1632). But `load_for_training` (:1674) and `load` (:1660) filter only on `split_role` and `kind`, so both copies would enter training and double-count. Reachability is low — `run_collect` refuses on `frozen_block_hash` or `config_hash` mismatch (:3149–3152) — but the store-level invariant is enforced at write time and not at read time.
- **`fan_identity` omits `seed_namespace`.** The tuple at :1468 covers `episode_seed, fan_epoch, kind, refan_k, policy_checkpoint_id, iteration` but not the namespace, so cross-namespace uniqueness rests entirely on episode-seed derivation one layer up. That derivation *is* domain-separated — `derive(cfg.run_seed, "preflight", i)` (:2937), `"train", i` (:3196), `"eval", i` (:3508), with `derive` length-prefixing each label (:104–107) — so a collision requires a 64-bit truncated-SHA-256 birthday collision across a few hundred seeds (negligible). The coupling is nonetheless implicit and undocumented at :1459.
- **Shard directory is never fsynced.** `mkdir` at :1582 and the first `open` for a new shard at :1595 are not followed by a directory fsync, so a host crash can lose the directory entry for a shard whose contents were fsynced. Minor, but it means the ≤`fsync_every` durability target is not strictly met for a shard's first 20 records.
- **`merge()` is whole-store, eager, and re-run per call.** `load` (:1660) and `load_for_training` (:1674) both decode every record in every shard — at a measured 14,187 bytes per fan record — then filter in memory. At the configured `n_collect = 300` (:175) with `fans_per_episode = 2` (:153) that is roughly 8.5 MB of JSON decoded per call, and preflight calls `merge()` three times (:2923, :2947, :2955). Acceptable at demo scale; no streaming or indexed path exists if scale grows.
- **Single flat schema for six kinds.** Four fields are kind-conditional nullable slots (`fan_epoch`, `refan_k`, `decisions`, `gate_results`), and nothing validates that a given kind populates the right ones — a `fan` with `gate_results` set, or a `policy_run` with `decisions=None`, constructs cleanly. Defensible as a single-file simplification, but the kind/payload correspondence is convention, not contract.

## Policy & Learning

**Location:** `experiments/kernel_demo.py` (lines 1682–1978) — author's sections 11 (POLICY, `:1680`) and 12 (LEARNING, `:1800`)

**Responsibility:** Defines the factored decision network (a Bernoulli WHEN gate plus a 4-way WHICH distribution over seeds), the deterministic deployment rule, and the frozen-temperature expected-reward objective that trains the network from fully-observed counterfactual-fan reward vectors on the train/tune splits only.

**Key Components:**
- `_PolicyBlock` (line 1682) - Hand-rolled pre-LN transformer block: explicit-matmul single-head self-attention at attention-dim = `d_model`, bias-free q/k/v/proj (`:1689–1692`), causal mask applied by `masked_fill(..., -inf)` before softmax (`:1700–1701`), MLP ratio 4 with GELU (`:1694`). No `nn.MultiheadAttention`, no SDPA, no dropout — deliberate, so the arithmetic is inspectable and hashable.
- `Policy` (line 1708) - The **trunk** is `embed` (Linear 20→d, GELU, Linear d→d, `:1716`) + learned positional parameter `pos[horizon, d]` scaled 0.02 (`:1717`) + `n_layers` `_PolicyBlock`s (`:1718`) + final LayerNorm (`:1719`), read out at the last valid token via `x[arange(b), lengths-1]` (`:1730`). The **factored head** is two named submodules that together form the conceptual `Linear(d_model, 5)`: `now_head: Linear(d,1)` → scalar WHEN/act logit (`:1720`, `:1731`) and `seed_head: Linear(d,4)` → WHICH logits over `SEED_NAMES` (`:1721`, `:1732`). They are separate modules for test addressability (`:1709–1711`; `tests/unit/kernel_demo/test_learning.py:57,68` grabs each head's parameters directly). **The policy outputs both**: a when-to-act Bernoulli AND a distribution over the 4 seeds. Init happens inside `rng_scope(gen)` (`:1715`) so weights are seed-derived.
- `schedule_only_mask` (line 1737) - The ablation comparator's mask. Builds `zeros_like(t)` and copies back only `[..., EPOCH_FEATURE_IDX]` (`:1741–1742`) — i.e. **masking is by ZEROING in normalized space, on the FEATURE axis**, not by `-inf` and not by field absence. 19 of 20 telemetry features are erased; only the clock survives. The comment (`:1738–1740`) records a fixed defect where a dim-0 implementation zeroed the batch axis instead. Pinned 1-D and `[B,T,D]` by `tests/unit/kernel_demo/test_policy.py:47–56`.
- `_policy_tokens` (line 1747) - `record_to_vector` → `normalizer.apply` → stack → `[1,T,20]` on the policy's device (`:1748–1750`). Normalize-then-mask ordering is fixed here and re-asserted at `:1766–1768` and `:1895`.
- `decide_live` (line 1754) - The declared deployment rule: return `(False, None)` outside the inclusive window `cfg.window` (`:1762–1765`), else normalize → mask → forward under `no_grad` with train-mode save/restore (`:1769–1773`), **raise `RuntimeError` on non-finite logits** rather than let `NaN > 0.5 == False` read as "never germinate, lift 0" (`:1774–1777`), fire iff `sigmoid(p) > 0.5` (`:1778`), pick `argmax` with lowest-index tie-break (`:1780`).
- `query_teacher_forced` (line 1786) - Non-firing read of `(p, {seed: π})` at a telemetry prefix's last epoch (`:1789–1797`). No window guard, no mask, no finiteness check — it measures, it does not decide.
- `_as_float` (line 1802) - **Silent-default audit: CLEAN.** Rejects `bool` explicitly before the numeric check (`:1805` — `bool` is an `int` subclass, correctly excluded) and raises `ValueError` on anything non-`(int, float)`, including `None` (a serialized non-finite). There is no default arm and no `.get()`.
- `_telemetry_vector_from_dict` (line 1811) - Decoded-dict twin of `record_to_vector` (`:397`). **Silent-default audit: CLEAN.** `f(key)` uses direct subscript `d[key]` (`:1814`), so a **missing key raises `KeyError`**, never 0.0; a `None`/string/bool value raises `ValueError` via `_as_float`; `f3` validates list-or-tuple *and* `len == 3` before conversion (`:1816–1820`). Builds exactly 20 fields in `record_to_vector` order (`:1822–1836`).
- `fan_to_example` (line 1840) - Fan record → training example `{tokens, length, r, r_noop}` (`:1847–1852`). **The label is the FULL 4-element reward vector**, not an argmax class and not a regret: `r[i] = by_name[SEED_NAMES[i]]["r_val"]` (`:1846`), plus the scalar `r_noop = by_name["noop"]["r_val"]` (`:1851`). **The no-op arm is NOT a fifth class** in `seed_head` (which is `Linear(d,4)`, `:1721`) — it enters only through the WHEN head's mixture at `:1904`. Rewards are **`r_val` only**; `r_test` never reaches a training example. Diverged arms carry `cfg.diverged_r = 0.10` from `run_arm` rather than being dropped (`:1841–1842`).
- `measure_fan_density` (line 1856) - Averages two reward *gaps* over records: `best_minus_second` = best seed arm minus runner-up (`:1865`) and `best_minus_noop` = best seed arm minus the no-op arm (`:1866`). These are the natural scales of the two decisions the factored head makes, and they set the two entropy temperatures. `unit="val"` is the **split selector**: `key = {"val": "r_val", "test": "r_test"}[unit]` (`:1859`), so `"val"` reads validation-split rewards and an unknown unit raises `KeyError`. Loud on empty input (`:1857–1858`, pinned by `test_learning.py:120`).
- `warmup_schedule` (line 1874) - Pure predicate `step >= round(total_steps * warmup_frac)` (`:1876`); `False` during warm-up disables `J_now` for the first 30% of steps (`cfg.warmup_frac = 0.3`, `:173`). Boundaries pinned by `test_learning.py:43–47`.
- `policy_loss` (line 1880) - **The objective is direct expected reward under full feedback, not cross-entropy and not a policy gradient.** Because the fan observes every arm, `J_which = Σ π_i r_i` is computed in closed form and differentiated exactly (`:1897–1898`) — no sampling, no REINFORCE, no baseline. Entropy bonuses on both heads use `clamp_min(1e-8)` before `log` (`:1899`, `:1905`). The WHEN term mixes `J_now = p·adv_mix + (1-p)·r_noop` where `adv_mix` uses `pi.detach()` (`:1903–1904`) — a **stop-gradient that prevents the WHEN head backpropagating into WHICH**, pinned by `test_learning.py:50–60`. Both temperatures are separate explicit keyword args (`:1885–1886`) because they map from two different density keys (`:1890–1892`).
- `_collate_examples` (line 1911) - Right-pads to batch-max `T` with zeros in normalized space (`:1915`, `:1920`) and records true `lengths` (`:1921`), which the trunk's last-valid-index readout consumes.
- `train_policy` (line 1928) - `_assert_trainable` first (`:1938`, raising `SplitViolation` on any eval-role or non-`fan` record). **Temperatures are frozen, not fitted**: `beta_which = cfg.beta_which_frac * frozen_density["best_minus_second"]` and `beta_now = frozen_density["best_minus_noop"] / cfg.beta_now_div` (`:1941–1942`), where `frozen_density` is a **required keyword-only parameter with no default** (`:1934`) — recomputation from `records` is impossible by signature. Split roles are read off the records, never recomputed (`:1944–1946`). Adam at `cfg.policy_lr` (`:1950`). **Checkpoint selection is on the TUNE split** — `tune_batch` is collated once from `tune_ex` (`:1955`) and scored every `total_steps // 10` steps under `no_grad`, keeping the lowest-scoring state dict (`:1964–1974`).

**Patterns Observed:**
- **Pre-registration chain for every fitted quantity, verified end to end.** The `Normalizer` is fit at preflight on preflight-namespace fans only (`:2956–2961`) and frozen into `frozen.json`; the density that sets both temperatures is measured on the same preflight fans (`:2963`, `:2880–2881`); `run_train` reads both back read-only (`:3347–3348`), re-derives the betas and *asserts* they match the manifest (`:3353–3354`), prints the train-set recomputation explicitly labelled "UNUSED for betas" (`:3352`), and refuses to run at all if the live config or source hash differs from the manifest (`:3343–3344`).
- **No train/eval leakage on this path — checked against every channel and found clean.** Training labels are `r_val` only (`:1846`, `:1851`); `r_test` appears solely on report and eval paths (`:3409`, `:3671`, `:3751`). Records reach training only through the train/tune filter (`:1674`) behind a guard placed on the yield path rather than vacuously behind the filter (`:1675–1676`), re-applied inside `train_policy` (`:1938`). **Checkpoint selection is on the tune split, not the evaluation split** (`:1955`, `:1964–1972`) — and eval-role records cannot physically reach the selector, since `_assert_trainable` raises on them first (`:1666`). `trained` and `schedule_only` are comparators reported side by side, not a best-of-two selected on test data (`:3358`).
- **The learning path honours the store's train/tune wall and never re-derives a split of its own** (cross-checked against explorer 5's storage-layer finding). `train_policy` partitions by reading the recorded field verbatim — `if r.split_role == "train"` / `== "tune"` (`:1945–1946`), under the standing comment "Records arrive pre-split into train/tune roles; never re-split" (`:1944`). There is no internal holdout, no `train_test_split`, no fraction, and no re-derivation of `train_tune_split` (`:1540`) anywhere in the range. Checkpoint selection reads **only** tune-role records: `tune_batch` is collated from `tune_ex` alone (`:1955`) and is the sole input to the scoring call (`:1966–1968`). Minibatch sampling cannot cross the wall by construction — `torch.randint(len(train_ex), ...)` (`:1957`) draws indices into the train list only, so the tune examples are outside the index space, and the draw is generator-seeded rather than globally shuffled. `_collate_examples` (`:1911–1924`) is pure padding and stacking: it preserves the order it is handed, and performs no shuffling, grouping, re-weighting, or cross-example mixing.
- **Episode identity is dropped at the training boundary, which enforces the wall but also forecloses episode-level grouping downstream.** Each episode yields exactly `cfg.fans_per_episode = 2` fans (`:153`, `:2340`, `:2348`), all stamped with one `split_role` computed once per episode before any fan exists (`:2339`), so a base trajectory cannot straddle the wall. But `fan_to_example` (`:1840`) returns only `{tokens, length, r, r_noop}` (`:1847–1852`) — `episode_seed` is not carried through. The learning path is therefore structurally incapable of grouping or clustering by episode, and its units are fans, not trajectories. Two bounded consequences, neither a wall violation and neither an inference claim: minibatches may contain both fans of one episode as if independent (harmless for SGD), and the full-batch tune score (`:1955`, `:1967`, mean at `:1907`) weights an episode by its surviving fan count — 2 normally, 1 or 0 where the base diverged and a snapshot was skipped (`:2352–2353`). The effect on checkpoint selection is small and bounded by that 2:1 ratio, but any future work wanting episode-clustered training or selection must re-add the identity field.
- **Loud-on-absence discipline throughout the decode boundary**, the project's silent-zero scar taken seriously: direct subscript rather than `.get()` (`:1814`), bool rejected as a number (`:1805`), 3-vector arity validated (`:1818`), non-finite logits raised rather than allowed to read as restraint (`:1774–1777`, mirrored at `:3397–3400`), empty density raised (`:1857`).
- **Three different masking mechanisms, each with different semantics** — attention causality by `-inf` fill (`:1700`), the schedule-only ablation by zeroing a feature slice (`:1741–1742`), and sequence padding by neither (zeros plus a `lengths` gather). **Location:** `experiments/kernel_demo.py` (lines 1979–2306, 2502–3062, 3265–3339);

**Responsibility:** Decides whether a run of the demo is permitted to produce a

**Key Components:**

**Patterns Observed:**
- **Content-addressed idempotency, not checkpoint files.** Resume everywhere keys on `fan_identity(...)` (line 1459) — `skip_fan_ids` inside `run_collection_episode` (lines 2349, 2383), the `existing` set in `run_eval` (line 3498), the `grid_missing`/`refan_done` predicates (lines 3620, 3641). Re-running a phase re-derives the same ids and skips what is already durable. Collection is genuinely idempotent at fan granularity: targets are `derive`-deterministic, the done-set is computed from the store, and nothing is double-appended.
- **No inter-worker write race by construction.** Each worker owns `shards/worker_<id>.jsonl` (line 1587) and a disjoint seed slice (line 3226); the skip set is computed once before spawn (line 3241) so no worker needs to see another's output. Worker 0's shard is reused across phases (collect `wid=0`, the `extension_event` at line 3162, every `run_eval` append) but always sequentially, never concurrently. `merge()` re-sorts by a canonical key so shard/append order never leaks to consumers (lines 1646–1656).
- **Halt channel = a shared `multiprocessing.Event` used as a cooperative global abort on determinism failure.** Created in the parent (line 3222), passed to every worker, set by whichever worker raises `TwinDivergence` (line 3116), polled between episodes (line 3096). `halted` propagates into the returned `ok` and the process exit code (lines 3248–3252).
- **Worker-crash detection is exit-code based and does not lose work.** `p.exitcode != 0` → `"crashed"`, `ok=False`, exit 1 (lines 3250–3251). A partial shard is not corruption: records were flushed on every append (line 1599), the missing fan is detected by the fan-level done-set on the next `collect`, and the surviving fan is skipped. A torn *final* line from a host crash is skipped with a warning; a torn *interior* line still raises (lines 1620–1629).
- **Layered admission checks that refuse before doing work.** Every phase re-validates the manifest before spending compute: collect (lines 3145–3154), worker (lines 3087–3092), train (line 3343), eval (lines 3462–3492), replay (lines 3943–3965). Messages name the remedy ("run preflight --freeze first", "run selftest --certify first").
- **Replay localises by checking re-derived inputs in causal order before blaming the kernel.** `run_replay` refuses on env keys, `config_hash`, `frozen_block_hash`, `manifest_hash`, `data_split_id` and `n_train`; then walks PATHOLOGY DERIVATION (line 3970) → FUTURE DERIVATION (line 3972) → SEEDING via `host_init_hash` (line 3976) → arm STATUS flip (line 3989) → KERNEL SELECTION on `r_val` inequality (line 4000). The `frozen_block_hash` check carries an explicit comment that without it a frozen-constant edit would masquerade as GPU nondeterminism (lines 3948–3950), and status-flip is checked before value comparison because it is the stronger signal (lines 3984–3986). Replay also reconstructs the *recorded* observation mode via `read_test = any(a.get("r_test") is not None ...)` (line 3962) rather than assuming one.
- **Comparator battery is four arms against a shared no-op, with the controls pre-registered as a hash-bound constant.** `EVAL_COMPARATORS` is a `semantic_const` (line 3261) so the control set is on the certified surface. `trained` (full telemetry, `p > 0.5`), `random` (uniform epoch in window + uniform seed, always acts, lines 3555–3558), `schedule_only` (masked telemetry, separately trained policy), `fixed_epoch` (trained WHICH head forced at `cfg.t_star`, lines 3559–3563). All four are scored as `r_test - r_noop_test` against **one** no-op run per episode (common random numbers). Never-germinating yields lift exactly 0 (line 3587).
- **The lift path is matched by re-derivation, not by branching from a shared snapshot.** `run_eval` never calls `take_snapshot`/`run_base`/`run_arm`/`run_fan`. The baseline is a separate episode — `noop_ctx = make_episode(...)` trained to the full horizon (lines 3512–3517) — and each comparator builds *another* independent episode from the same seed (line 3542, inside the comparator loop) and germinates mid-run. Matching rests on `make_episode` (line 1014) being a pure function of `(cfg, data, device, episode_seed, read_test)` — pathology from `derive(es,"pathology")`, host from `derive(es,"host-init")`, CommonFuture from `derive(es,"future",0)` — plus `train_one_epoch` (line 1057) drawing batch order, crops and flips from the precomputed `ctx.future` tensors, with no global-RNG consumption and no dropout in the loop. So common random numbers **are** shared and the pre-germination prefixes **are** identical under determinism. The gap is that nothing verifies it — see the first Concern.
- **No comparator is advantaged by seeing data the policy does not, and no threshold is tuned post-hoc.** The policy is queried only on recorded telemetry; test accuracy enters solely as the teacher-forced *target* (`_test_argmax`), never as a policy input, and `run_report` publishes `p_val_argmax_eq_test_argmax` (line 3892) as the diagnostic for that gap. `AGREEMENT_MARGIN`, `N_EVAL_REFANS` and the verdict thresholds are `semantic_const`s bound into `config_hash`; `sigma_r_floor` for the power note is read from the *frozen* gate-3 result (lines 3769–3770), not recomputed on eval data. `fixed_epoch` deliberately inherits the trained WHICH head so the WHEN contrast isolates timing. The one structural asymmetry — `random` and `fixed_epoch` always act while `trained` and `schedule_only` may abstain, so cross-comparator mean lift mixes decision quality with action rate — is *measured and reported*, not hidden: `restraint_regret` (lines 3733–3760, including a per-grid-point table explicitly labelled as containing option value) and `when_contrast` (line 3800, paired `trained − fixed_epoch` with an unrestricted and a germinated-only mean, the latter `None` rather than 0.0 when undefined).
- **Statistical units are chosen against the clustering, and the choice is commented.** The falsifier null CI and the agreement MDE use the *episode* count, not the grid-point count, because the grid is 2 points per episode (lines 3693–3698, 3814–3816). The money chart has a diverged-excluded companion so the diagonal can be checked against divergence-avoidance (lines 3718–3732).
