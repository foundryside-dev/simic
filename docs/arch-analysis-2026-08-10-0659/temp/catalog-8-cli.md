## Run Orchestration & CLI

**Location:** `experiments/kernel_demo.py` (lines 2307–2501, 3063–3264, 3340–4066); `experiments/__init__.py` (0 lines, empty package marker)

**Responsibility:** Drives the demo end to end — the shared episode/schedule machinery every phase reuses, the spawn-based parallel collection layer with its halt channel and fan-level crash resume, and the seven-subcommand CLI that trains the policy, runs the pre-registered comparator battery, prints the result tables and verifies bitwise replay.

**Key Components:**
- `draw_schedule` (line 2307) - draws the 2 ordered fan epochs per episode: `torch.randperm` over the inclusive `cfg.window`, seeded by `derive(episode_seed, label)`; the `label` argument separates the collection draw (`"schedule"`) from the frozen eval grid draw (`"evalgrid"`) over the same distribution (line 2310). The `a, b = sorted(...)` unpack (line 2314) deliberately fails loudly if `fans_per_episode != 2`.
- `run_collection_episode` (line 2319) - one collection episode end to end: assigns `split_role` (`preflight`/`eval` by namespace, else `train_tune_split(episode_seed)` recorded once and never re-split, line 2339) → draws the schedule → `make_episode` → `state_hash(ctx.host)` as `host_init` → `run_base` with the fan epochs → per fan epoch, `run_fan` on the snapshot and one `fan` record appended. A 1-in-10 null-seed subsample is wired into the *collection* path, not just selftest (line 2347). If the base diverged, a `void_event` record carries `diverged_at` and the skipped fan epochs (lines 2382–2414) — failures are retained, not dropped.
- `run_refan` (line 2418) - re-fans an episode at a given epoch under a *fresh* `CommonFuture` (line 2469) with 5 arms including a re-based no-op, because the base tail is not a valid comparand (line 2470–2471). A `TelemetryDivergence` during base replay is recorded as a `refan_k`-distinct `void_event` and skipped rather than raised, so a deterministic replay divergence cannot brick preflight/eval on every retry (lines 2437–2467).
- `worker_main` (line 3063) - the spawned collection worker. `enable_class1()` is the first statement (line 3077); stdout/stderr are redirected into `logs/worker_<id>.log` (line 3085); data is loaded once per process; the worker independently refuses if `frozen.json`'s `n_train` differs from the live bundle (lines 3087–3092). It iterates its seed slice, checks `halt.is_set()` between episodes, and on `TwinDivergence` writes a divergence report, sets `halt` and breaks (lines 3114–3118). `store.close()` in a `finally` (line 3123).
- `run_collect` (line 3132) - the parallel driver. Four admission checks before anything spawns: `frozen.json` exists, `frozen_block_hash` matches, `config_hash` matches, and all manifest gates ok (lines 3145–3154). `--extend` appends an `extension_event` whose `iteration` is derived from store state (line 3174). Targets are `derive(cfg.run_seed, "train", i)` for `n_collect + extensions`; the done-set is fan-level (voided, or `>= fans_per_episode` fans) so a crash between an episode's two fans resumes the missing one (lines 3199–3215). Workers are spawned with `multiprocessing.get_context("spawn")` (line 3221), seeds partitioned `todo[wid::len(slots)]` (line 3226), and each receives the same `frozenset(existing_ids)` skip set (line 3241).
- `run_train` (line 3340) - trains two policies (`trained`, and `schedule_only` under `schedule_only_mask`). Betas come from the *manifest* density, never from the collected records; the collection recomputation is printed and explicitly labelled UNUSED (lines 3349–3354), with asserts pinning the manifest betas to the frozen density. Checkpoints are keyed by `state_hash(policy)` (line 3364).
- `_load_policy` (line 3376), `_query_dicts` (line 3385), `_test_argmax` (line 3405), `_pi_argmax` (line 3416) - eval helpers. `_query_dicts` raises on non-finite policy output rather than letting `NaN > 0.5 == False` read as restraint (lines 3397–3400). `_pi_argmax` pins the tie-break to lowest `SEED_NAMES` index, matching `decide_live` (lines 3417–3419).
- `run_eval` (line 3425) - ~400 lines; the comparator battery. One-shot guarded on `eval_results.json` (line 3431); manifest, `n_train` and collection-completeness admission checks (lines 3462–3492); four comparators from `EVAL_COMPARATORS` (line 3261) run per eval episode against a single shared `r_noop_test` (lines 3512–3519); frozen 2-point eval grid via `draw_schedule(es, cfg, "evalgrid")` (line 3619); up to `N_EVAL_REFANS` refans (line 3645); then teacher-forced agreement, the class-derangement falsifier, the ceiling estimate, sign-flip p-values, the money chart, restraint regret and the WHEN contrast, assembled into `results` and stamped with `verdict(results, cfg)` (line 3820) before an atomic `os.replace` write (line 3823).
- `run_report` (line 3829) - D6 mixed-`manifest_hash` refusal (lines 3834–3839) then the D4 aligned tables: per-comparator mean lift and germination rate, agreement vs both nulls, money chart matched/4 with p, and the verdict (lines 3909–3920), plus a JSON report carrying observed diverged end-states beside the `diverged_r` convention, per-seed failure rates, `g_at_germination`, `p_val_argmax_eq_test_argmax`, and the realized-p-by-sign(A) diagnostic.
- `run_replay` (line 3925) - bitwise replay with staged localisation (see Patterns).
- `main` (line 4004) - the single CLI dispatcher; `enable_class1()` first (line 4005), `MODES` (line 240) as the subcommand set.

**Patterns Observed:**
- **Content-addressed idempotency, not checkpoint files.** Resume everywhere keys on `fan_identity(...)` (line 1459) — `skip_fan_ids` inside `run_collection_episode` (lines 2349, 2383), the `existing` set in `run_eval` (line 3498), the `grid_missing`/`refan_done` predicates (lines 3620, 3641). Re-running a phase re-derives the same ids and skips what is already durable. Collection is genuinely idempotent at fan granularity: targets are `derive`-deterministic, the done-set is computed from the store, and nothing is double-appended.
- **No inter-worker write race by construction.** Each worker owns `shards/worker_<id>.jsonl` (line 1587) and a disjoint seed slice (line 3226); the skip set is computed once before spawn (line 3241) so no worker needs to see another's output. Worker 0's shard is reused across phases (collect `wid=0`, the `extension_event` at line 3162, every `run_eval` append) but always sequentially, never concurrently. `merge()` re-sorts by a canonical key so shard/append order never leaks to consumers (lines 1646–1656).
- **Halt channel = a shared `multiprocessing.Event` used as a cooperative global abort on determinism failure.** Created in the parent (line 3222), passed to every worker, set by whichever worker raises `TwinDivergence` (line 3116), polled between episodes (line 3096). `halted` propagates into the returned `ok` and the process exit code (lines 3248–3252).
- **Worker-crash detection is exit-code based and does not lose work.** `p.exitcode != 0` → `"crashed"`, `ok=False`, exit 1 (lines 3250–3251). A partial shard is not corruption: records were flushed on every append (line 1599), the missing fan is detected by the fan-level done-set on the next `collect`, and the surviving fan is skipped. A torn *final* line from a host crash is skipped with a warning; a torn *interior* line still raises (lines 1620–1629).
- **Layered admission checks that refuse before doing work.** Every phase re-validates the manifest before spending compute: collect (lines 3145–3154), worker (lines 3087–3092), train (line 3343), eval (lines 3462–3492), replay (lines 3943–3965). Messages name the remedy ("run preflight --freeze first", "run selftest --certify first").
- **Replay localises by checking re-derived inputs in causal order before blaming the kernel.** `run_replay` refuses on env keys, `config_hash`, `frozen_block_hash`, `manifest_hash`, `data_split_id` and `n_train`; then walks PATHOLOGY DERIVATION (line 3970) → FUTURE DERIVATION (line 3972) → SEEDING via `host_init_hash` (line 3976) → arm STATUS flip (line 3989) → KERNEL SELECTION on `r_val` inequality (line 4000). The `frozen_block_hash` check carries an explicit comment that without it a frozen-constant edit would masquerade as GPU nondeterminism (lines 3948–3950), and status-flip is checked before value comparison because it is the stronger signal (lines 3984–3986). Replay also reconstructs the *recorded* observation mode via `read_test = any(a.get("r_test") is not None ...)` (line 3962) rather than assuming one.
- **Comparator battery is four arms against a shared no-op, with the controls pre-registered as a hash-bound constant.** `EVAL_COMPARATORS` is a `semantic_const` (line 3261) so the control set is on the certified surface. `trained` (full telemetry, `p > 0.5`), `random` (uniform epoch in window + uniform seed, always acts, lines 3555–3558), `schedule_only` (masked telemetry, separately trained policy), `fixed_epoch` (trained WHICH head forced at `cfg.t_star`, lines 3559–3563). All four are scored as `r_test - r_noop_test` against **one** no-op run per episode (common random numbers). Never-germinating yields lift exactly 0 (line 3587).
- **The lift path is matched by re-derivation, not by branching from a shared snapshot.** `run_eval` never calls `take_snapshot`/`run_base`/`run_arm`/`run_fan`. The baseline is a separate episode — `noop_ctx = make_episode(...)` trained to the full horizon (lines 3512–3517) — and each comparator builds *another* independent episode from the same seed (line 3542, inside the comparator loop) and germinates mid-run. Matching rests on `make_episode` (line 1014) being a pure function of `(cfg, data, device, episode_seed, read_test)` — pathology from `derive(es,"pathology")`, host from `derive(es,"host-init")`, CommonFuture from `derive(es,"future",0)` — plus `train_one_epoch` (line 1057) drawing batch order, crops and flips from the precomputed `ctx.future` tensors, with no global-RNG consumption and no dropout in the loop. So common random numbers **are** shared and the pre-germination prefixes **are** identical under determinism. The gap is that nothing verifies it — see the first Concern.
- **No comparator is advantaged by seeing data the policy does not, and no threshold is tuned post-hoc.** The policy is queried only on recorded telemetry; test accuracy enters solely as the teacher-forced *target* (`_test_argmax`), never as a policy input, and `run_report` publishes `p_val_argmax_eq_test_argmax` (line 3892) as the diagnostic for that gap. `AGREEMENT_MARGIN`, `N_EVAL_REFANS` and the verdict thresholds are `semantic_const`s bound into `config_hash`; `sigma_r_floor` for the power note is read from the *frozen* gate-3 result (lines 3769–3770), not recomputed on eval data. `fixed_epoch` deliberately inherits the trained WHICH head so the WHEN contrast isolates timing. The one structural asymmetry — `random` and `fixed_epoch` always act while `trained` and `schedule_only` may abstain, so cross-comparator mean lift mixes decision quality with action rate — is *measured and reported*, not hidden: `restraint_regret` (lines 3733–3760, including a per-grid-point table explicitly labelled as containing option value) and `when_contrast` (line 3800, paired `trained − fixed_epoch` with an unrestricted and a germinated-only mean, the latter `None` rather than 0.0 when undefined).
- **Statistical units are chosen against the clustering, and the choice is commented.** The falsifier null CI and the agreement MDE use the *episode* count, not the grid-point count, because the grid is 2 points per episode (lines 3693–3698, 3814–3816). The money chart has a diverged-excluded companion so the diagonal can be checked against divergence-avoidance (lines 3718–3732).
- **Every store write is either append-only-with-flush or an atomic `os.replace`** (`eval_results.json` line 3823, `divergence_*.json` line 3059, `frozen.json` line 2914, `certified.json` line 2300).
- **Anti-silent-default discipline on the resume path.** A resumed `policy_run` record with a missing or malformed `decisions` payload raises rather than defaulting to "never germinated, lift 0", with the scar named in the comment (lines 3524–3531).
- **Dependency injection as a test seam.** `run_collect` takes `data_loader` and `episode_runner` as keyword defaults (lines 3140–3141) so the parallel layer can be exercised without CUDA or CIFAR; both are module-level functions, so `spawn` pickles them by reference.

## Plotting Sidecar

**Location:** `experiments/kernel_demo_plots.py` (lines 1–433, entire file); `tests/unit/kernel_demo/test_plots.py` (lines 1–239). Both analysed at commit **`aa86388`** — see Confidence.

**Responsibility:** Standalone matplotlib CLI that renders up to five diagnostic figures plus a provenance manifest from an explicitly-selected, unambiguous slice of a record store and/or `eval_results.json`, built on the rule that a missing datum is an error rather than a zero.

**Key Components:**
- Module docstring (lines 1–12) - carries two claims: the original separation claim (*"plots never touch the semantic surface"*) and a new reporting-discipline contract — *"this module never invents a datum. A missing required field is an error, not a zero; a store holding more than one experimental population is refused rather than pooled; an absent measurement is labelled absent rather than plotted at the origin."*
- `PlotDataError` (line 34) - single typed failure class for missing, malformed or ambiguous input.
- `require_number` (line 38) / `require_dict` (line 55) - direct indexing with typed refusal, explicitly *not* `.get(<default>)` (line 39); `require_number` also rejects non-finite values on the grounds that `_sanitize_json` writes non-finite as null, so a live NaN means the producer changed (lines 48–51).
- `_finite_points` (line 65) / `_gapped` (line 83) - keep the *original* index with each value and re-emit `nan` at dropped positions, so a null mid-curve leaves a visible gap instead of silently relabelling the epoch axis (lines 66–68, 84–85).
- `_spike_then_crash` (line 93) - now compares the peak against the kernel's own `end_state_R` (mean of the final three) rather than the bare final point, guarding the <3-entry case that `end_state_R` raises on.
- `_provenance` (line 105) - `"{seed_namespace}/{split_role} fan_epoch={fan_epoch}"`, rendered into subplot titles.
- `_load_fans` (line 109) - the selection layer: existence checks on the store root and `shards/` run **before** `Store(...)` is constructed (lines 122–128), then `Store.load` for split_role or `merge()`, then namespace and manifest filters, then refusal if the surviving population spans more than one namespace (line 148) or more than one manifest generation (line 151).
- `plot_example_arm_curves` (line 156) - renamed from `plot_arm_curves`; "example, not *the*" (line 157), one record per pathology by canonical merge order, provenance in each subplot title (line 182), selected `fan_id`s returned for the manifest, and an explicit "no plottable curve_val" annotation when a panel is empty (line 189).
- `_logged_arms` (line 197) / `plot_alpha_beta` (line 205) - generator plus `islice(..., MAX_ALPHA_BETA_ARMS)` so the four-arm bound holds *by construction* rather than being checked between records (lines 206–208); x-axis relabelled "completed epochs since germination" starting at 1, because entry 0 is the state after the first completed post-germination epoch (lines 222–224).
- `plot_money_chart_trio` (line 242) - every value validated up front (lines 243–252); each panel now carries its pre-registered verdict rule as a dashed line (lines 256–274).
- `plot_tune_curve` (line 282) - distinguishes three cases: absent file → skip (line 285), present-but-empty curve → skip as a legitimate empty tune split (lines 289–297), missing `curve` key or no finite entries → refuse (lines 293–300).
- `plot_rms_blend_entry` (line 315) - a seed with no measurement is omitted from the boxplot, named in a `missing` list, and annotated on the figure (lines 330–359); `n=` is shown per box.
- `main` (line 367) - new `--namespace`, `--split-role`, `--manifest`, `--include-refans`; `ap.error` if neither `--store` nor `--results` (line 377); all input validation precedes the output `mkdir` (lines 380–399); writes `plot_manifest.json` recording the selection and the files written (lines 400–427).
- `tests/unit/kernel_demo/test_plots.py` - 16 tests organised around the four named fabrication modes (docstring lines 3–6): missing field read as zero, absent measurement drawn at the origin, epoch axis silently relabelled, mistyped store path creating an empty store and reporting success.

**Dependencies:**
- Inbound: None from the fixed subsystem list — no subsystem imports or invokes the sidecar. Its sole importer in the repository is the test module `tests/unit/kernel_demo/test_plots.py`, which is test scaffolding rather than a catalogued subsystem.
- Outbound: Run Orchestration & CLI (consumes `eval_results.json` from `run_eval` and `policies/trained.json` from `run_train`; imports `AGREEMENT_MARGIN`, `kernel_demo.py:3256`); Records & Store (`FanRecord`, `Store`, `Store.load`, and `make_fan_record` in the tests); Host, Seeds & Slot Lifecycle (`SEED_NAMES`, `kernel_demo.py:634`); Counterfactual Fan Executor (imports `end_state_R`, `kernel_demo.py:1188`, and reads the `ArmResult` fields `curve_val`, `alpha_beta_log`, `rms_ratio_blend_entry`, `status`)

**Patterns Observed:**
- **Refusal over defaulting, applied systematically.** The `.get(<default>)` pattern is gone; `require_number`/`require_dict` raise a typed `PlotDataError` naming the field and its context. The comment at line 39 states the reasoning explicitly — *"a wrong or truncated results file must fail here rather than become a chart of zeros"* — which is the same discipline `kernel_demo.py` applies at its own resume boundary (lines 3524–3531).
- **Absence is represented, not substituted.** Three distinct absences get three distinct treatments: a null mid-curve becomes a visible `nan` gap at its true index (lines 83–90); a seed with no blend-entry measurement is dropped from the boxplot and named on the figure (lines 330–359); a legitimately-empty tune curve is skipped rather than plotted or refused (lines 296–297). The alternative — plotting each at the origin — is called out as the defect being avoided (lines 330–332).
- **Population ambiguity is refused rather than pooled.** `_load_fans` will not silently merge seed namespaces or manifest generations (lines 147–152). This is *stricter* than the kernel's own D6 check in `run_report` (`kernel_demo.py:3835`), which inspects only eval-namespace records.
- **Ordering discipline: validate, then mutate the filesystem.** Store-root existence is checked before `Store(...)` mkdirs `shards/` (lines 122–128), and all input validation precedes the output `mkdir` (lines 380–381). Both are pinned by tests that assert the directory was *not* created (test lines 69–81).
- **Reuse of kernel definitions instead of local re-derivation.** `end_state_R` and `AGREEMENT_MARGIN` are imported rather than reimplemented (line 28), so the spike-then-crash rule and the agreement threshold line move with the certified surface. The test at lines 141–151 deliberately exercises a curve on which the imported definition and the old local one disagree.
- **Bounded by construction, and the bound is recorded.** `islice` replaces a between-records counter (lines 206–212); the arms actually drawn are returned and written into `plot_manifest.json` (line 416), so truncation is disclosed in the artifact.
- **Every figure is closed in a `finally`** (lines 192, 237, 278, 310, 362) — a refusal mid-plot cannot leak a matplotlib figure.
- **The optional-dependency and hash-surface separation both still hold.** The import edge remains one-way; the sidecar declares no `@semantic`/`semantic_const`, so nothing in it enters `config_hash`. Importing certified *values* from the kernel is the correct direction and strengthens rather than weakens the claim.

**Concerns:**
- **The docstring's population-refusal invariant is enforced on two of its three axes.** `_load_fans` refuses a mixed *namespace* (line 148) and a mixed *manifest generation* (line 151), but never refuses a mixed `split_role` — it filters when `--split-role` is given and pools silently when it is not (lines 135–138). A `--namespace train` store legitimately holds both `train` and `tune` roles (`train_tune_split`, `kernel_demo.py:1540`), and `tune` is the held-out selection split, so pooling them into one RMS boxplot is exactly the "fabricated aggregate" the comment at lines 117–119 says it is guarding against. The test suite pins that split_role *selection* works (test lines 191–199) but never tests refusal on a mixed store, because there is none.
- **`--include-refans` pools two different measurements under one flag.** A `refan` is re-fanned under a *fresh* CommonFuture (`kernel_demo.py:2469`) — a materially different comparand from a `fan`, which is why the kernel keeps them as distinct record kinds. With the flag set they land in the same boxplot and the same alpha/beta panel with no label distinguishing them, and `_provenance` (line 105) does not include `kind`. The flag is untested: every `_load_fans` call in the suite passes `include_refans=False`.
- **The mixed-manifest guard excludes `manifest_hash=None` records from its own ambiguity check.** Line 150 filters `if r.manifest_hash is not None` before counting generations, so a population mixing hashed and un-hashed records reads as a single generation and is pooled; passing `--manifest m0` then silently *drops* the un-hashed ones (line 140). This is latent rather than live today: the records that carry `manifest_hash=None` are preflight fans (`kernel_demo.py:2941` passes no `manifest_hash`), and those also carry `seed_namespace="preflight"`, so the namespace guard catches the realistic mixture. The guard is therefore correct only because namespace happens to correlate with manifest presence — nothing enforces that coupling, and the None-exclusion would stop working the moment it broke.
- **`plot_manifest.json` records which records were selected but not what drew them.** It captures paths, selectors, `record_count`, `manifest_hashes_present`, chosen `fan_id`s and the file list (lines 400–427) — genuinely useful, and the best provenance any artifact in the sidecar has ever had. What it omits is the producing code: no `config_hash()`, no sidecar git rev or version, and no record of `SPIKE_CRASH_MARGIN`. So the manifest cannot answer "which plotting code, with which thresholds, drew this PNG" — precisely the question the kernel's `config_hash`/`manifest_hash` machinery exists to answer for every other artifact in the run.
- **`SPIKE_CRASH_MARGIN` (line 30) survives, and composing it with a certified function arguably makes it harder to notice.** `_spike_then_crash` now calls the kernel's `@semantic` `end_state_R` (line 102), so the rule *looks* kernel-derived — but the 0.05 margin that decides the verdict is still local, not in `Config`, not in `frozen.json`, and not hash-bound. The test at lines 141–151 demonstrates the classification is threshold-sensitive by construction (it picks a curve where the old and new rules disagree). A "(spike-then-crash)" label in a legend remains an uncertified analytic claim that can be changed with no hash moving and no replay refusing. `MAX_ALPHA_BETA_ARMS` (line 31) is a second local constant, though display-only.
- **One of the two verdict thresholds drawn on the money-chart trio is imported; the other is hardcoded.** Panel 2 correctly draws `majority + AGREEMENT_MARGIN` from the imported `semantic_const` (line 265). Panel 1 hardcodes `axhline(3, …, label="required matches")` (line 259) and `set_ylim(0, 4.2)` (line 260), duplicating the `>= 3` rule that `verdict()` owns at `kernel_demo.py:3323` and the 4-pathology denominator. A change to the pre-registered money-chart rule would move the verdict and leave the chart's own reference line stale — and the chart is the artifact a reader trusts. The author demonstrably knows the right pattern, having applied it one panel over.
- **A refusal partway through `main` leaves unattributed PNGs and a stale manifest.** Figures are written incrementally (lines 414–424) and `plot_manifest.json` is written last (line 427). If, say, `plot_alpha_beta` raises, `example_arm_curves.png` is already on disk with no manifest describing it — and if the directory holds a *previous* successful run's `plot_manifest.json`, that file now describes a different set of images than the ones present. The provenance artifact is the one thing that should be crash-consistent with the images, and it is the least protected: no temp-directory staging, no atomic `os.replace` (which `kernel_demo.py` uses for every artifact it writes — lines 2914, 3059, 3823), and no manifest-first-then-rename.
- **`plot_alpha_beta` refuses on a legitimate absence, unlike its sibling.** Line 229 raises `PlotDataError("no arm carried a non-empty alpha_beta_log")`. But an all-diverged fan population has no non-empty logs — a state the kernel names explicitly (`_all_arms_diverged`, `kernel_demo.py:2515`) and therefore treats as legitimate. `plot_tune_curve` handles its equivalent case by returning `False` and skipping (line 297); `plot_alpha_beta` aborts the whole run, *after* `example_arm_curves.png` has been written, triggering the partial-output hazard above. The two functions apply opposite policies to the same class of legitimate absence.
- **`_finite_points` silently drops non-finite values while `require_number` refuses them.** Line 78 keeps a value only `if math.isfinite(f)`, so an `inf` in a curve is dropped and rendered as a gap indistinguishable from a recorded null. `require_number` treats exactly that condition as proof the producer changed and refuses (lines 48–51). Two validators in one module, opposite policies on the same input class; the `_finite_points` behaviour is the one that loses information.
- **No exit-code discipline.** `main` does not catch `PlotDataError`, so a refusal surfaces as an uncaught traceback (exit 1) rather than a diagnostic line — workable, but the sidecar has no equivalent of `kernel_demo.py`'s explicit `SystemExit` handling (lines 4035–4062), and no test asserts the exit status of a failing invocation.
- **Test-suite gaps, in order of exposure:** no test that a mixed train/tune store is refused (there is no such refusal — first Concern); `--include-refans` is never exercised; no test of the `--results`-only path through `main` (every `main` test passes `--store`); no test of the partial-output/stale-manifest case; `_provenance` output is never asserted, so nothing pins the subplot-title contents; and no assertion on process exit status for any refusal. The suite is well-aimed at the four fabrication modes it names and does not claim to cover selection semantics beyond them.
