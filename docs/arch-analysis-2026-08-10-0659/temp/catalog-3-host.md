## Host, Seeds & Slot Lifecycle

**Location:** `experiments/kernel_demo.py` (lines 538–916)

**Responsibility:** Defines the four-pathology host CNN, the fixed four-seed menu behind a single `gain * f(h)` delta contract, and the DORMANT→FOSSILIZED slot state machine that admits a seed's influence without ever letting it perturb the host's forward trajectory during training.

**Key Components:**
- `PATHOLOGIES` (line 539) - `semantic_const` naming the four host defects in canonical order: `("under_normalized", "channel_starved", "no_spatial_mix", "mild")`. Indexed by `derive(episode_seed, "pathology") % 4` (:1017) to assign each episode a host defect, and used as the axis for per-pathology gate reporting.
- `DESIGNED_WINNER` (line 543) - `semantic_const` mapping each pathology to the seed expected to win it (`under_normalized→norm`, `channel_starved→conv_heavy`, `no_spatial_mix→attn`, `mild→conv_light`). This is the demo's **pre-registered falsifiable prediction**: it is the comparand for the money test's permutation analysis (:3716, :3727) and is reported alongside observed winners at :2628. It is a `semantic_const`, so it is hashed into `config_hash` — the prediction cannot be silently edited after the fact.
- `Host` (line 555) - 3-stage CIFAR CNN (`stage1`/`stage2`/`stage3` + GAP + `fc`). All pathology wiring is in `__init__` (:558–576) so an edit moves `config_hash`; `build_host` is plumbing only. `forward(x, slot)` (:602) injects the slot between stage2 and stage3.
- `Host._make_stage` (line 578) - conv→norm→ReLU→conv→norm→ReLU→MaxPool2d; `use_bn=False` swaps both norms for `nn.Identity`, `gain != 1.0` scales both conv weights in-place under `no_grad` (:590–593).
- `Host.forward_to_slot` (line 598) - stage1→stage2, the slot site; `[B, 64, 8, 8]` for every pathology.
- `Host.attach_stat_hooks` / `_saturation_hook` (lines 614, 620) - forward hooks on each stage's last ReLU (`stage[5]`) writing dead-unit fraction into `stage_stats["saturation"]`.
- `build_host` (line 628) - constructs `Host` inside `rng_scope(make_generator(init_seed))`; the only randomness entry point for host init.
- `SEED_NAMES` (line 634) - `("norm", "attn", "conv_light", "conv_heavy")`; the canonical ordering consumed repo-wide for arm indexing.
- `SeedDelta` (line 638) - the delta contract. `forward(h) = self.gain * self.f(h)`; `gain` is a 0-dim `nn.Parameter` born `torch.zeros(())` and is the sole carrier of τ. Subclasses implement `f` only.
- `NormSeed` (line 653) - `GroupNorm(8, channels)`; `f = gn(h) - h`, so `gain=1` yields exactly `GN(h)` — an interpolation toward normalized. 129 params.
- `AttnSeed` (line 663) - explicit single-head attention over the 64 spatial tokens, `d=16`, hand-written softmax rather than SDPA (spec: visible, deterministic arithmetic). 4,337 params.
- `ConvLightSeed` (line 687) - depthwise 3×3 → 1×1 to `mid=64` → BN → ReLU → 1×1 back. 8,897 params.
- `ConvHeavySeed` (line 704) - 3×3 to `cb=52` → BN → ReLU → 3×3 back → BN (final BN γ=1). 60,137 params.
- `build_seed` (line 721) - name→class dispatch inside `rng_scope`; raises `ValueError` on unknown name (:729).
- `tau_init` (line 735) - "D11" data-dependent scale calibration; sets `gain = cfg.tau * rms(host_feats) / max(rms(f0), cfg.tau_eps)` (:745–746) so the seed's delta enters at τ=5% of host-feature RMS.
- `split_decay_groups` (line 751) - partitions `named_parameters()` into decay / no-decay by `param.ndim <= 1 or name.endswith("gain")`.
- `Stage` (line 769) - 6-state enum; `GERMINATED` is zero-duration by design (D12).
- `cosine_ease` (line 779) - clamped `0.5*(1-cos(pi*p))` ramp shared by both schedules.
- `Slot` (line 785) - the lifecycle module. `forward` (:807) applies STE or α-blend; `trust_region_loss` (:822); `rms_ratio` (:829); `step_tick` (:838) advances per-step ramps; `epoch_tick` (:853) drives stage transitions and appends `alpha_beta_log`.
- `build_optimizer` (line 874) - 2-group SGD (decay/no-decay), `momentum=0.9`, `nesterov=True`, **constant LR by deliberate design**.
- `append_seed_group` (line 892) - adds the germinated seed as two further groups at `cfg.seed_lr` with fresh momentum.
- `FORBIDDEN_RELAXATIONS` (line 900) - 9-entry tuple naming every change that voids the Class-1 determinism claim: disabling the twin arm, disabling deterministic algorithms, enabling TF32, enabling `cudnn.benchmark`, enabling AMP, adding gradient clipping, **adding dropout**, running fans across devices, and `torch.compile` (D10). Explicitly **documentation-only** — deliberately not a `semantic_const` (:901–903), so it is printed by `--selftest` but is not hashed into `config_hash` and not mechanically enforced.

**Patterns Observed:**
- **Uniform delta contract, verified empirically.** All four seeds take `channels: int`, map `[B,64,8,8] → [B,64,8,8]`, and produce an exactly-zero delta at construction (`gain=0`). After `tau_init` all four land at `rms(gain*f(h))/rms(h) = 0.0500` — exactly `cfg.tau` — despite `rms(f0)` differing by orders of magnitude across seeds (measured g: 0.9215 / 0.3307 / 0.1187 / 0.04998). The τ-normalization is what makes structurally dissimilar seeds enter on a common scale.
- **The seed is NOT a no-op at germination — the STE is.** `germinate` (:1181) tau-inits `gain` to a *nonzero* value, then `Slot.forward` (:819) returns `h + (delta - delta.detach())` during `TRAINING`: the forward value is bitwise `h`, while the seed still receives full gradients. The no-op property is provided by the estimator, not by a zero gain. Verified: `torch.equal(h + (d - d.detach()), h)` is True for finite `d`.
- **α and β gate different things, and β is specifically *upstream*.** α (:820) scales the delta into the forward value; β (:814) interpolates `hin` between `h.detach()` and `h`, controlling gradient flow *back into stage1/stage2 through the delta branch*. Measured: extra upstream gradient beyond the identity path is **exactly 0.000000 at β=0 in every stage**, and scales ~linearly with β (0 → ~400 → ~800 at β=0/0.5/1.0). Since β only ramps in `FOSSILIZING` (:850), the host is gradient-isolated from the seed branch for the whole of TRAINING and BLENDING.
- **Lifecycle trace.** DORMANT →(`germinate`, :1184, skipping GERMINATED)→ TRAINING (`stage_k`=3 epochs; STE, α unused, β=0, trust region active) → BLENDING (`stage_m`=3; α cosine-ramps 0→1 per step, forced to 1.0 at exit :865) → FOSSILIZING (`stage_f`=2; β cosine-ramps 0→1) → FOSSILIZED (α=β=1, :867–869). Transitions are epoch-granular, ramps step-granular.
- **The trust region exists precisely because the STE hides the delta.** `trust_region_loss` (:827) is `λ·mean(δ²)/mean(h.detach()²)` and self-gates to `TRAINING` only (:825). Under STE the CE loss cannot constrain δ's magnitude at all (forward value is `h` regardless), so this relative-magnitude penalty is the only thing bounding δ before α turns up. `λ=1.0` is documented as inside the stability bound `λ < 1/seed_lr ≈ 20` (:823).
- **The classic add-param-group bug is anticipated and structurally designed out.** The comment at :874–878 names it: `lr_scheduler` captures `base_lrs` positionally at construction, so a group appended at germination would mismatch — constant LR removes the class rather than patching it. Verified empirically: `add_param_group` preserves existing momentum buffers exactly (state is keyed by parameter object, not group index), new params correctly start with no state (fresh momentum), and the new groups inherit `momentum=0.9`/`nesterov=True` from `defaults` while overriding `lr`/`weight_decay`. **No corruption of existing momentum or LR.**
- **Double-germination is refused, not tolerated.** `germinate` (:1169–1173) raises unless the slot is `DORMANT`, explicitly to prevent duplicate optimizer groups silently orphaning a prior seed.
- **Parameter ownership is partitioned by construction, not by filtering.** `Slot` is never a submodule of `Host` (verified: `any(m is slot for m in host.modules())` is False; seed params absent from both `host.named_parameters()` and `host.state_dict()`). This is why `build_optimizer(host, …)` cannot double-count seed params and why snapshots (:1143) are always clean 2-group never-germinated state.
- **Decay partition is total and correctly typed.** `ndim <= 1` catches biases and all norm affines even under `nn.Sequential`'s integer names, where substring rules would mis-file BN affines (:754–756). Every parameter reaches exactly one group; nothing is dropped from the optimizer.
- **The STE's bitwise claim is soundly defended at both edges.** Bitwise identity holds for finite δ (verified), but `-0.0 + 0.0 = +0.0` flips the sign bit and `-0.0` does survive ReLU and MaxPool (verified). Both hazards are already closed: `state_hash` (:933–945) explicitly zero-normalizes for exactly this reason (D8), and a non-finite delta poisons telemetry into `TelemetryDivergence` (:375), scoring the arm `diverged_r`. Residual is attribution only — a seed-side NaN presents as a host/telemetry divergence rather than a seed fault.
- **No stochastic operations anywhere in the model path — clean negative, verified exhaustively.** Neither `Host` (:555), `Slot` (:785), nor any of the four `SeedDelta` subclasses (:653, :663, :687, :704) draws from the global torch RNG during forward or backward. Two independent verifications: (a) a module-type audit across all 4 pathologies and all 4 seeds finds only `Conv2d`/`BatchNorm2d`/`Identity`/`ReLU`/`MaxPool2d`/`AdaptiveAvgPool2d`/`Linear`/`GroupNorm`/`LayerNorm`/`Sequential` — zero `Dropout`/`AlphaDropout`/`RNNBase` instances; (b) a state-comparison probe over **all 80 combinations** of pathology × seed × stage (DORMANT/TRAINING/BLENDING/FOSSILIZING/FOSSILIZED), running full forward + `loss.backward()` + `opt.step()` + `step_tick`/`epoch_tick`, found the global RNG state byte-identical before and after in every case. A positive control (`torch.randn` → True) confirms the probe detects draws. `AttnSeed` in particular has no attention dropout (:676–683), and BatchNorm's train-mode running-stat update consumes no RNG.
- **Construction is RNG-isolated from the global stream too.** `build_host` (:628), `build_seed` (:721) and `tau_init` (:735) all leave the global stream byte-unchanged, because `rng_scope` (:123–133) swaps in the generator's state and restores the prior global state in its `finally`. Verified: host init is bitwise reproducible from the same `init_seed` under deliberately differing ambient global RNG state. So germination does not perturb the global stream either.
- **Fail-loud discipline.** `Host.__init__` (:560) and `build_seed` (:728) raise on unknown names; `rms_ratio` (:833) raises rather than returning a sentinel if called before an armed forward.

**Concerns:**
- **The seed parameter budget floor is a comment, not a check.** `ConvLightSeed` (:690) cites "the budget floor (2,657 / 4,737 params)" as the reason `mid=16/32` is rejected, and `ConvHeavySeed` (:707) cites a "valid band [31, 77]" for `cb`. Grep finds no `numel`/param-count gate anywhere in the seed path or the certification battery. In a file that hashes its own source and runs an 8-gate preflight battery, a stated design constraint with zero mechanical enforcement is an outlier — a future edit to `mid`/`cb` would pass every gate silently. Measured menu spread is **129 / 4,337 / 8,897 / 60,137 params (466×)**, so the menu is not capacity-matched; whether that confounds "which seed wins" is a fairness question owned by the Certification Battery.
- **`tau_init` calibrates on a validation batch.** `germinate` (:1178) draws `ctx.data.val_x[:cfg.batch_size]` as the measurement batch, and the arm reward is computed in VAL units (`r_val`, :1846). The seed's birth scale is therefore a (single-scalar, 128-example) function of validation data. The magnitude is small and the fixed batch is deterministic by design, but it is a genuine val-touching initialization path and belongs in the statistics/leakage review rather than being assumed benign. A `read_test` path exists (:1011), which suggests the author is aware of the concern.
- **`FORBIDDEN_RELAXATIONS` (:900) is documentation-only and is the sole guard on the no-runtime-RNG property.** The tuple is deliberately not a `semantic_const` (:901–903), so it is printed by `--selftest` but never hashed into `config_hash` and never mechanically checked. The model path's RNG-free property (see Patterns) is a *current-code* fact, not a structurally enforced one: the single change most likely to break it — "adding dropout" — is named in this list, but only as prose. A future edit adding `nn.Dropout` to a seed would make the global stream genuinely load-bearing for cross-arm matching while passing every gate. The list also does not mention the arm-sequencing requirement that `torch.set_rng_state` being process-global implies (flagged by the Counterfactual Fan Executor analysis).
- **No upper clamp on the tau-init gain.** `max(rms_f0, cfg.tau_eps)` (:745) guards the denominator from below with `tau_eps=1e-6`, but if `rms(f0)` were near-degenerate — most plausibly `NormSeed` on already-well-normalized features, where `f = GN(h) - h → 0` — `g` grows without bound. Gate 5's `rms_ratio` band (:2692–2710) would detect the consequence, but only at blend entry and only in preflight, not at germination where the value is set.
- **`NormSeed` receives no weight decay at all.** Its decay group is empty (all of `gain`, `gn.weight`, `gn.bias` are ndim ≤ 1) — verified: `decay=0, no_decay=3`. `append_seed_group` (:895) then registers an empty param group, which PyTorch accepts and steps over harmlessly (verified). The behaviour follows correctly from the rule and is arguably right for a pure-norm seed, but it means the four arms carry structurally different regularization exposure, compounding the capacity spread above.
- **`last_delta`/`last_h` are mutable cross-call state on an `nn.Module` (:795–796, :816–817).** Every `forward` writes them, including `evaluate_acc`'s eval-mode `no_grad` forwards (:1046–1050) on validation data. Correctness of `trust_region_loss` currently rests on `train_one_epoch` always calling `host(x, slot)` immediately before reading it (:1071→:1073) — ordering, not construction. Were that ordering ever broken, the trust term would silently degrade to a graph-less constant rather than failing loudly, which cuts against this file's own stated allergy to silent zeros (:1085). Currently unreachable; flagged as fragility, not a live defect.
- **`feat_channels = 64` is hardcoded (:575), not derived from `w2` (:563).** The 64-wide slot *is* genuinely fixed across all four pathologies — `mild` alters only `w1`/`w3` (:565) and `channel_starved` alters only stage2's *mid* channel (:569), leaving `out_ch = w2 = 64` — and this is confirmed empirically (`f.shape=(8,64,8,8)` for all seeds). But the invariant is maintained by two independent literals rather than one, so a future width edit would desynchronize the host from the seed constructor.
