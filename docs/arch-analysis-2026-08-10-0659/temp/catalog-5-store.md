## Records & Store

**Location:** `experiments/kernel_demo.py` (lines 1420–1681, author's "section 10 — RECORDS AND STORE")

**Responsibility:** Defines the single on-disk record schema (`FanRecord`), its content-derived identity, its JSON codec, the train/tune split decision, and a sharded append-only JSONL store that every other section writes through and reads back from.

**Key Components:**

- `SplitViolation` (line 1420) — `RuntimeError` subclass; the typed failure class for the "split wall". Explicitly opted out of the semantic surface at :1424 with a stated reason ("no computation depends on its definition"), consistent with the `_NON_SEMANTIC` discipline at :87–97.
- `RECORD_KINDS` / `SEED_NAMESPACES` / `SPLIT_ROLES` (lines 1426–1428) — the three closed vocabularies. Six kinds (`fan`, `refan`, `policy_run`, `preflight_iter`, `extension_event`, `void_event`), four namespaces, four split roles. Enforced as whitelists at :1501–1506.
- `FanRecord` (line 1433) — 21-field flat dataclass, one shape for all six kinds. Kind-specific payloads are nullable slots (`decisions` :1453 for `policy_run`, `gate_results` :1454 for `preflight_iter`) rather than a discriminated union. Carries four identity/provenance hashes (`config_hash`, `frozen_block_hash`, `manifest_hash`, `common_future_hash`) plus `host_init_hash`, binding every record to the source, config, freeze generation, data future, and initial host state that produced it. Measured size of a realistic 40-epoch fan record: **14,187 bytes encoded**.
- `fan_identity(...)` (line 1459) — SHA-256 over `json.dumps([episode_seed, fan_epoch, kind, refan_k, policy_checkpoint_id, iteration])`. A **content hash over a composite key**, not a counter. Deterministic and stable across re-runs: every component is derived from episode/store state, never wall-clock or process-local counters (stated intent at :1498–1500). This is what makes collection idempotent — `run_collect` builds a skip-set of existing `fan_id`s (:3205–3215) and `run_collection_episode` skips any fan already durable (:2349, :2383).
- `make_fan_record(...)` (line 1473) — keyword-only sole constructor. Validates all three vocabularies before construction (:1501–1506, `ValueError` on unknown), stamps `SCHEMA_VERSION` (:1508), and derives `fan_id` (:1529) so identity can never diverge from content.
- `make_schedule_id(cfg)` (line 1534) — hashes the sampling policy string plus `cfg.window` and `cfg.fans_per_episode`.
- `train_tune_split(episode_seed)` (line 1540) — `"tune" if derive(episode_seed, "tune-split") % 5 == 0 else "train"`; ~20% tune.
- `_sanitize_json` (line 1547) — recursive; non-finite floats → `None`, tuples → lists.
- `encode_record` / `decode_record` (lines 1560, 1565) — JSONL codec with a fail-closed `schema_version` equality check (:1567–1573).
- `Store` (line 1579) — shard-per-writer JSONL store rooted at `<root>/shards/worker_<id>.jsonl`, with `append` (:1590), `close` (:1604), `merge` (:1612), `load` (:1659).
- `_assert_trainable` / `load_for_training` (lines 1664, 1673) — the split wall and the only sanctioned training read path.

**Patterns Observed:**

- **Content-addressed identity over counters.** `fan_identity` (:1459) hashes the full identity tuple, so a resumed run reconstructs identical ids and re-collection is idempotent. The comment at :1498–1500 names the rule explicitly: `iteration` and `policy_checkpoint_id` must come from store state or content identity. Call sites honour it — `iteration=len(ext_events)` (:3174) and `iteration=len([...void_event])` (:3448) are both derived from a `merge()` of the store, never a process counter.
- **Split decided once, at collection time, and recorded.** `train_tune_split` (:1540) is a pure function of `episode_seed` via `derive`; the call site at :2339 stamps it onto the episode before any fan is produced, and every fan of that episode inherits the same `split_role` (:2367). **The grouped-statistics hazard is closed:** one base trajectory cannot straddle train and tune, because the split is a function of episode identity rather than arrival order or record identity, and it is never recomputed downstream (`load_for_training` :1674 and the tune filter at :1946 read the recorded field). The `refan` path never assigns train/tune at all — it hardcodes `"preflight" if namespace == "preflight" else "eval"` (:2447, :2478), so refans cannot leak into training.
- **Fail-closed schema versioning.** `decode_record` (:1567) raises on any `schema_version` inequality rather than attempting migration, and the error text (:1569–1572) states the governing policy: additive-only post-collection, non-additive bumps are an owner decision, "never silent."
- **Non-finite encoded as `null`, and the null is loud downstream.** `_sanitize_json` (:1550–1551) maps NaN/Inf to `null` rather than emitting JSON's non-standard `NaN` literal. The lossiness is deliberately paired with `_as_float` (:1802–1807), which raises on `None` and on any non-numeric — so a serialized non-finite reaching the numeric path raises rather than silently becoming zero. Round-trip is directly tested (selftest :2194–2199; `tests/unit/kernel_demo/test_store.py:66`). **Float precision is preserved exactly:** `json.dumps` serializes floats via `float.__repr__` (shortest round-tripping repr), not a fixed format.
- **Torn-final-line tolerance is real and correct for the simple case.** `merge()` (:1617–1629) catches `JSONDecodeError`, and if the bad line is the file's last it prints a loud warning and continues; only an *interior* bad line re-raises. The stated rationale (:1622–1626) is that a torn final line is a host crash mid-append whose record was never durable, i.e. the ≤`fsync_every` contract operating as designed rather than corruption. **Verified by execution:** a store torn mid-record merges to exactly its prior records with a warning. `test_store.py:98` covers both halves of this.
- **Single-record appends are atomic against concurrent writers.** Mode `"a"` (:1595) sets `O_APPEND` (verified), and the flush-on-every-append at :1599 keeps the buffer empty so each record leaves Python as exactly **one** `write()` syscall — measured as 1 raw call for payloads of 14 KB, 1 MB, and 10 MB, with no partial writes. On Linux + ext4 the kernel holds the inode lock across a buffered regular-file write, so `O_APPEND` position-and-content are atomic together. **Verified empirically:** 8 concurrent processes × 300 appends of 14 KB records into one shard produced 2,400/2,400 valid, distinct lines and zero malformed lines.
- **Shard-per-writer as the concurrency strategy.** `run_collect` assigns each spawned process a unique `wid` from `enumerate(slots)` (:3225), gives it a disjoint seed slice `todo[wid::len(slots)]` (:3226), and has the parent call `store.close()` (:3216) *before* spawning. Within one invocation the scheme is sound.
- **Canonical merged order, independent of write order.** `merge()` sorts on a 7-tuple (:1646–1655) with `None`-coalescing to `-1` and trailing discriminators (`policy_checkpoint_id`, `iteration`, `fan_id`) chosen so that kinds the leading key cannot separate still order deterministically. The comment at :1644–1645 states the invariant: "shard-file/append order must never leak into consumers."
- **Duplicate detection as a hard stop.** `merge()` (:1633–1639) raises `ValueError` on a repeated `(manifest_hash, fan_id)` for `fan`/`refan`. Exercised by appending the same record to two shards (selftest :2210–2215; `test_store.py:90`).
- **Graded durability with a stated target.** Flush on every append (:1599) — process crash loses nothing; `os.fsync` every `fsync_every` records (:1601–1602, default 20 at :179) — host crash loses ≤ 20. `close()` (:1604–1610) flushes and fsyncs every handle. Correct ordering (Python buffer flush before `fsync`).
- **Typed, asymmetric split wall.** `_assert_trainable` (:1664) distinguishes two violations with distinct messages — an eval-split record on the training path (:1667) and a wrong-kind record (:1669) — rather than one generic assert. Tested on the yield path (`test_store.py:133`).
- **Vocabulary-driven validation with no escape hatch.** All three whitelists (:1426–1428) are checked in the sole constructor, so an invalid record cannot be built, let alone written.
- **Clean one-way dependency: the persistence layer is a verified leaf.** Records & Store depends on exactly one other subsystem — the identity/config spine — and on nothing else in the file; six of the seven other subsystems depend on *it*. Established mechanically rather than by reading declarations: an AST pass over every `Name` load in 1420–1681 resolves to `semantic`, `_NON_SEMANTIC`, `SCHEMA_VERSION`, `derive` and `Config`, and a second pass over every attribute access finds no read of any foreign shape. This is the property you would design for and rarely get — the layer that defines the on-disk contract is not entangled with the producers or consumers of the data it carries, so the schema can be reasoned about, versioned, and tested in isolation (as `test_store.py` in fact does, with no fan, host, or policy fixtures). Worth stating positively, because the same structure in the parent programme's terms is a dependency-direction rule: contracts import nothing from the subsystems that use them. **The isolation is achieved but not enforced** — the single-file layout (a locked spec decision, so by design) means there is no module boundary or import gate to keep it true, and no linter would catch a future edit that reached from this range into the fan or telemetry sections. It holds by discipline, and it currently holds completely.
- **Deliberate payload opacity.** `arms` and `telemetry` are declared `list[dict[str, object]]` (:1451–1452) and the store never inspects them: an AST inventory of every attribute access in the range finds zero field-name reads of any payload shape. The whitelists validate the record's *envelope* — kind, namespace, split role — and nothing validates its *contents*. This is coherent with the store's job and is why it takes no dependency on the sections that produce the payloads; the cost is in the next bullet.

**Concerns:**

- **A record written after a torn tail is silently lost, behind a warning that is byte-identical to the benign case.** This is the section's most serious defect and it is a silent-loss bug, not merely an availability one. `append` opens mode `"a"` (:1595) and writes the newline as a *suffix* (:1598), so a partial line carries no terminator and the next append fuses onto it. **Reproduced end to end against the real `Store`:** (A) tear a shard mid-record → `merge()` returns the 2 prior records with the warning, correct; (B) resume and append a third record → the file still has 3 lines, the new record having fused into the partial one; (C) `merge()` returns **2 records — the record just written is gone**, behind the identical `"skipping torn final line"` message from :1627, indistinguishable from (A); (D) one further append makes the fused line interior → `merge()` raises → the store is unreadable by every consumer. The apparent mitigation is the trigger: the lost `fan_id` is absent from the `merge()`-derived skip set (:3157), so collection re-runs it — and that re-collection append is exactly step (D). `test_store.py:98` covers (A) and a hand-built interior tear, but **never appends after a tear**, so (B)–(D) are untested. Fix is one line at shard open: seek to the last newline and `truncate()`, or write the newline as a prefix.
- **Severity note — validity is protected, availability is not.** The blast radius of the above stops short of a wrong published number. A pre-existing torn tail crashes `run_preflight` at its very first `store.merge()` (:2922–2923) *before any gate runs*, so freeze is fail-closed against it; and `run_eval` refuses on an episode-count shortfall (:3491–3492, `"eval refused: incomplete collection"`), so a quietly-dropped episode cannot silently shrink the eval population. The cost is a bricked collection run and its compute, plus operator confusion — not a corrupted result. That distinction should survive into the final report.
- **Interior corruption escapes as an untyped `json.JSONDecodeError`.** The re-raise at :1629 propagates the raw decode error out of `merge()`. Every other failure mode in this file has a named class (`SplitViolation` :1420, and `TelemetryDivergence` / `TwinDivergence` elsewhere), and `test_store.py:104` only passes because `JSONDecodeError` subclasses `ValueError`. Store corruption is a distinct operational condition and deserves a distinct class, consistent with the module's own typed-failure discipline.
- **No writer exclusion on shard files — but the failure is loud, not silent.** There is no lockfile, PID guard, or `O_EXCL` anywhere in the module (verified by negative grep). Two concurrent `--collect` invocations against one store root each start `wid` at 0 (:3225) and write into the same shard. Having established that appends are line-atomic, the outcome is **duplicate-but-valid records, not malformed lines** — so the first thing to fire is `merge()`'s duplication backstop at :1638 (`ValueError: duplicate fan_id`), the designed refusal working exactly as intended. The store still becomes unreadable until the duplicate lines are removed, but this is a tractable, typed, loud failure rather than byte-level corruption. Downgraded accordingly; a store-root lockfile remains the cheap fix, and the atomicity guarantee should be written down as a load-bearing assumption since it is platform-scoped (Linux + local ext4; **NFS `O_APPEND` does not provide it**).
- **Payload opacity makes the store a silent conduit for shape drift.** Because nothing between producer and consumer inspects the payload, two different `arms` shapes travel the same pipe undetected: the full 12-field `ArmResult` via `dataclasses.asdict` (:2376, :2492) and hand-built partial dicts of four or five keys (`:2188` — `name`/`status`/`r_val`/`curve_val`; `:3608` — `name`/`status`/`r_val`/`r_test`). Consumers read fields by name off the merged result (:1845, :2511, :2517) and would raise `KeyError` on the wrong shape, at read time, against data already durable on disk. The store cannot catch this by design, but it is the component through which the drift flows, and the envelope/contents asymmetry above is exactly the gap: `RECORD_KINDS` is enforced, arm shape is not. A `kind`-conditional payload check in `make_fan_record` would close it at write time. Note for the dependency matrix: these `serialized-shape` edges run **producer → consumer** and pass *through* Records & Store without touching it — renaming `ArmResult.r_val` breaks Policy & Learning and the Certification Battery while leaving this section entirely unaffected, so routing them as store-adjacent edges would misattribute the change impact.
- **`decode_record` is a tolerant reader with no current beneficiary.** `kwargs = {f.name: data.get(f.name) for f in dataclasses.fields(FanRecord)}` (:1574) fills any absent field with `None` at the *same* `schema_version`. `SCHEMA_VERSION = 1` (:55) means there are zero additive-evolution cases today, so the tolerance is currently pure hazard: a field-dropping record decodes without complaint, and a `None` `split_role` would drop it from the training filter (:1674) silently, while a `None` `episode_seed` would surface only as a `TypeError` in the sort key (:1648). Mitigated but not closed by `_as_float`'s loud `None` handling (:1802–1807), which covers the numeric path only. A required-field non-`None` check after construction would close it.
- **A skipped torn record leaves only a stdout `print`, not a record.** The warning at :1627 goes to stdout with `flush=True`. In a store whose stated premise is complete append-only history — `void_event` exists precisely so failures stay on the record (:2383, :2442) — a lost record that survives only in a console log is a coherence gap with the design's own discipline, and it is what makes the silent-loss step above so hard to notice.
- **`manifest_hash` is in the dedup key but not in any read filter.** `merge()` keys collisions on `(manifest_hash, fan_id)` (:1636), deliberately permitting the same fan under two freeze generations (comment :1630–1632). But `load_for_training` (:1674) and `load` (:1660) filter only on `split_role` and `kind`, so both copies would enter training and double-count. Reachability is low — `run_collect` refuses on `frozen_block_hash` or `config_hash` mismatch (:3149–3152) — but the store-level invariant is enforced at write time and not at read time.
- **`fan_identity` omits `seed_namespace`.** The tuple at :1468 covers `episode_seed, fan_epoch, kind, refan_k, policy_checkpoint_id, iteration` but not the namespace, so cross-namespace uniqueness rests entirely on episode-seed derivation one layer up. That derivation *is* domain-separated — `derive(cfg.run_seed, "preflight", i)` (:2937), `"train", i` (:3196), `"eval", i` (:3508), with `derive` length-prefixing each label (:104–107) — so a collision requires a 64-bit truncated-SHA-256 birthday collision across a few hundred seeds (negligible). The coupling is nonetheless implicit and undocumented at :1459.
- **Shard directory is never fsynced.** `mkdir` at :1582 and the first `open` for a new shard at :1595 are not followed by a directory fsync, so a host crash can lose the directory entry for a shard whose contents were fsynced. Minor, but it means the ≤`fsync_every` durability target is not strictly met for a shard's first 20 records.
- **`merge()` is whole-store, eager, and re-run per call.** `load` (:1660) and `load_for_training` (:1674) both decode every record in every shard — at a measured 14,187 bytes per fan record — then filter in memory. At the configured `n_collect = 300` (:175) with `fans_per_episode = 2` (:153) that is roughly 8.5 MB of JSON decoded per call, and preflight calls `merge()` three times (:2923, :2947, :2955). Acceptable at demo scale; no streaming or indexed path exists if scale grows.
- **Single flat schema for six kinds.** Four fields are kind-conditional nullable slots (`fan_epoch`, `refan_k`, `decisions`, `gate_results`), and nothing validates that a given kind populates the right ones — a `fan` with `gate_results` set, or a `policy_run` with `decisions=None`, constructs cleanly. Defensible as a single-file simplification, but the kind/payload correspondence is convention, not contract.
